# 조목조목 — 원문 근거로 검토하는 규정 제·개정 도우미

2026 공공 AI 대전환 챌린지 세션 2 지정과제 ③ 규정 제·개정 에이전트. 이 문서는 **v0.9 구현 기준, 2026-10-27 인수인계판**입니다. 실제 통합 검사·운영 배포·모델 응답의 확인 범위와 미확인 항목은 [v0.8 검증 기록](docs/VALIDATION-v0.8.md)을 기준으로 합니다. 아래 기능 설명 자체가 운영 검증 완료를 뜻하지는 않습니다.

조목조목은 개정 의도에서 조문 수정안·연쇄 인용 정비·문서 세트까지 이어지는 작업 도구입니다. AI가 제안한 변경을 담당자가 확인하면, 확정된 변경 명세를 문서 엔진이 공통으로 사용합니다. v0.4에서는 제공된 핵심 입안 자료 5종과 출처 안내를 검색해 AI 요청에 넣고, 답변에 사용한 원문 페이지와 내려받기 파일을 함께 보여 줍니다.

## v0.9 — 절차까지 이어지는 에이전트, 법령 단위 확장, 쉬운 시작

- **④ 절차·일정 진행판(과제 선택기능 ‘절차 단계별 지원’):** 기관 설정의 절차를 작업별 진행판으로 바꿉니다. 단계마다 대기·진행 중·완료·해당 없음과 예정·완료일·메모를 기록하면 ‘지금 할 일’과 준비 문서를 안내하고, 문서 세트에 **추진 일정표**를 추가합니다.
- **법정 기한 계산기:** 예고 시작일·의결일·이송일·공포 예정일로 의견제출 마감(자치법규 20일·법령 40일), 조례 이송(5일)·공포/재의요구(20일)·보고(5일), 규칙 보고(공포 예정일 15일 전)를 계산합니다. 초일 불산입·말일 휴일 이월(「민법」 제157조·제161조)과 2026~2027 관공서 공휴일을 반영하고, 마감일을 예고문에 바로 넣습니다. 기존 예고 기간 계산의 주말 미반영도 바로잡았습니다.
- **법령 단위 범위 확장(선택기능):** 법률·대통령령·총리령·부령을 규정 종류에 추가했습니다. 「법령 입안·심사 기준」에 따라 `○○법 일부개정법률안`, `○○법 시행령 일부개정령안`, `이 법/영/규칙은 공포한 날부터 시행한다.`를 생성하고, 법령 전용 입안 점검표 8항목(형식·위임·체계·규제·시행일·경과조치·벌칙·개정 방식)과 정부입법 절차(입법예고 40일·규제심사·법제처 심사·국무회의·공포)를 적용합니다. 가상 중앙행정기관 `한빛부`와 ‘시행령 고치기 예시’를 추가했습니다.
- **할 일 중심 홈과 쉬운 시작 화면:** 홈을 ‘오늘은 어떤 일을 하시나요?’ 네 갈래(제정·개정·상위법 영향·조사)로 정리하고, 표정 조절판은 작은 버튼으로 줄였습니다. 시작 화면은 법제처 검색을 먼저 보여 주고, 규정 종류를 자치법규·행정규칙·공공기관·국가 법령으로 묶었습니다. 기본 색을 조목이 화면의 청록 계열로 통일했습니다.
- **배포 환경 중립 안내·문장 정비:** 키가 없을 때의 안내를 특정 호스팅(Vercel)에 묶지 않고 ‘시스템 담당자에게 서버 환경변수 설정 요청’으로 바꿨습니다. 점검 메시지의 조사 오류(“제9조제2항”는 → 은)를 고쳤습니다.
- **검증:** 신규 회귀검사 13개(기한 계산·진행판·보관파일 왕복·법령 제명/부칙·이전 기관 설정 호환·조사)를 포함해 전체 자동 검사를 통과합니다.

## v0.8 — 자료의 판단 순서를 업무와 문서로 연결

- **조문별 권한·근거표:** 적용 대상·사무 성격·주민 부담·근거 원문과 허용 범위·담당자 판단을 연결합니다. 일반 자치사무에 개별 위임을 일률적으로 요구하지 않으며 유사 조례·매뉴얼을 위임 근거로 승인하지 않습니다.
- **기존 업무와 부칙:** 신청·계약·위원 임기·제재·서식 준비를 구분합니다. 현재 본문에 대해 직접 확인한 적용례·특례·경과조치만 출력하고, 본문·시행일 변경 후에는 재확인을 요청합니다.
- **전부개정·폐지:** 새 본칙 전체 편집과 전용 제목·지시문·붙임을 제공합니다. 종전 부칙을 자동 승계하지 않으며, 새 본문이 없으면 원문을 완성한 전부개정안처럼 출력하지 않습니다.
- **행정규칙 일몰 검토:** 부칙 자동 삽입을 제거했습니다. 적용 대상과 기관 기준을 확인한 조문을 본칙 마지막에 명시적으로 추가할 수 있습니다. 유효기간과 재검토기한을 구분합니다.
- **의견제시·예고 후 처리:** 공식 요청서의 항목을 채운 작성자료와 제출의견 처리·통지·재예고 검토 기록을 출력합니다. 요청서는 원본 배치에 직접 기입한 문서와 구분하고 원본 다운로드도 유지합니다.
- **여러 규정의 영향 후보:** 최대 8개 규정의 정확한 법규명·조문·별표·서식 인용을 대조합니다. 번호 이동·삭제·본문 변경·전부개정·폐지 후보를 구분하며 자동 정비완료로 처리하지 않습니다.
- **쟁점별 RAG 검색:** 입력 본문 전체에서 쟁점을 찾고 6개·5,500자 예산 안에서 근거를 배분합니다. 입력 범위·근거 미발견·예산 제외도 검토 기록에 남깁니다.
- **작업 보관·문서 일치:** 새 입력과 재확인 상태를 JSON 보관파일 및 HWPX·DOCX에 함께 보존합니다. 다운로드는 검토·절차의 자동 완료가 아닙니다.

## v0.7 — 큰 조목이와 친숙한 시작 화면

- **홈의 안내자:** 큰 조목이와 “조목이와 함께, 규정 제·개정 쉽게 시작해요” 문구, 새 규정·기존 규정의 두 시작 행동을 함께 제공합니다. 문서 예시는 다음 영역에서 확인합니다.
- **표정과 움직임:** 인사·미소·활짝 웃음·생각·응원·다정함을 눈·입·팔·몸짓으로 구분합니다. 직접 표정을 고르면 그 표정에 머물고, 자동 전환과 움직임을 각각 조절할 수 있습니다. 시스템의 움직임 줄이기 설정과 숨겨진 탭 상태를 따릅니다.
- **업무 중의 조목이:** 시작·AI 작성·다음 할 일·검토·파일 준비 상태에 맞춰 안내합니다. 작은 업무 화면의 움직임은 한 번만 재생하며, AI 처리 중에는 생각하는 동작을 반복합니다. 반영 뒤 초안이 다시 바뀌면 성공 표정을 유지하지 않습니다.
- **핵심 자료 5종을 다시 대조:** PDF 4권·요청서 1종과 추가 출처 안내를 명확히 구분했습니다. 원본·검색·현재 기능을 대조한 후속 기획과 별도의 독립 평가표를 작성했습니다. 계획한 기능을 구현 완료로 계산하지 않습니다.
- **추가 AI 호출 없는 캐릭터:** SVG·CSS로 표시하므로 캐릭터 움직임 때문에 AI API를 호출하거나 새 제공자 키를 요구하지 않습니다. 공식 HWPX·DOCX에는 캐릭터를 넣지 않습니다.

## v0.6 — 조목이와 현재 작업을 함께 검토

- **눈에 띄는 다음 할 일:** 조문·점검·문서 단계와 실제 작성 상태에 맞춰 큰 제목과 한 가지 주된 행동을 안내합니다. 조·항·호·목 색인과 연필을 가진 조목이는 안내 화면에만 등장하며 공식 문서에는 들어가지 않습니다.
- **작업 안에서 AI 검토:** 다른 페이지로 나가지 않고 현재 초안과 부칙을 선택해 검토합니다. 피드백·수정 제안과 원문 인용의 시각적 위계를 구분합니다.
- **선택한 수정 반영·되돌리기:** 현재 본문과 정확히 일치하는 고유한 문구만 선택해 적용합니다. 오래된 결과·겹친 범위·모호한 대상은 자동 반영하지 않습니다. 개정 원문을 보존하며 문서 엔진에 같은 변경을 전달합니다.
- **검토 중에도 문서 저장:** 화면에 만들어진 문서는 미확인 여부를 표시한 검토용 HWPX·DOCX로 받을 수 있습니다. 조문 확인이나 이유서 확인을 자동 수락하지 않습니다. 문서가 바뀌면 이전에 만든 다운로드 파일도 구분합니다.
- **자료실 요청 시간 정렬:** 자료실 AI 검토도 Vercel 300초·제공자 처리 270초·브라우저 대기 310초를 사용합니다. 제공자 요청 한도와 호스팅 실행 시간을 별도로 안내합니다.

## v0.5에서 추가한 작업 흐름

- **조례 조사·5개년 비교:** 공포연도별 현행 목록과 연혁 목록을 함께 조회하고, 같은 공포 기록은 합쳐 제정·개정·폐지를 비교합니다. 조회하지 못한 페이지와 남은 페이지를 표시하고 이어서 조회할 수 있습니다. 같은 조례의 두 공포 버전은 실제 조문을 나란히 비교합니다.
- **조사에서 입안까지:** 현재 유효한 원문을 다시 조회해 새 규정의 참고자료 또는 현행 조례 개정 작업으로 가져갑니다. 조회 범위와 시점도 함께 남깁니다. 과거 버전을 현행 원문으로 바꾸어 표시하지 않습니다.
- **유사 규정 최대 4개:** 위임 조항·유사 규정 패널을 처음부터 펼쳐 놓고, 검색어를 바꾸어도 이미 선택한 규정을 유지합니다. 3개를 기본 비교 대상으로 삼고 필요하면 4번째를 추가할 수 있습니다. 모든 선택 자료를 AI 참고 근거에 전달합니다.
- **길어진 제정 초안 작성:** 최대 3개 조씩 순서대로 작성하고, 완성한 묶음은 브라우저 저장을 확인한 후 다음 요청으로 넘어갑니다. 중단·오류 후에는 빈 조문만 이어 쓰며 직접 수정한 본문은 보존합니다. 애니메이션과 경과 시간, 실제 완료 조문 수, 중단 버튼을 제공합니다.
- **문서별 HWPX·DOCX:** 예고문 공고번호·날짜·제출처와 입안 점검 상태를 직접 입력하고 개별 문서 또는 전체 세트로 받습니다. 제공 매뉴얼의 편집 기준과 점검 항목을 적용했습니다. 구조 검사와 실제 한컴 한글 검수의 범위는 구분합니다. [서식 근거](docs/research/v05-form-mapping.md)

## 기존 입안 자료·RAG 작업 흐름

- **입안 자료실:** PDF 4권의 실제 1,997쪽, HWPX 요청서 1개, 사용자 출처 안내 1개를 검색하고 원본 5종과 추가 출처 안내를 내려받습니다. 판본·수록 기준·수집 시점·실제 PDF 쪽수·파일 지문을 함께 표시합니다.
- **자료 근거 AI 도움:** 기준 물어보기, 초안 검토, 알기 쉬운 문장, 의견제시 요청 준비의 네 가지 방식입니다. 실제 검색된 출처에 있는 인용문을 서버에서 대조하고, AI 설명에 실패해도 검색 원문을 보여 줍니다.
- **제·개정 작업의 RAG:** 개정 계획, 제정 조문체계와 초안, 이유·주요내용, 점검 결과 정비, 상위법 영향 검토에 관련 입안 자료를 전달합니다. 작업 화면과 보관파일에는 실제 전달한 참고 발췌문을 남깁니다.
- **유사 규정 참고:** 공식 API로 원문을 조회하고 최대 4개 규정을 선택해 실제 조 제목·본문을 비교합니다. 다른 기관의 규정이 우리 기관의 위임 근거가 되는 것으로 처리하지 않습니다.
- **기관 설정 이전:** 기관명·서식·절차를 편집하고 JSON으로 내보내거나 불러올 수 있습니다. 새 작업에는 당시 기관 설정을 보관하므로 나중에 설정을 고쳐도 진행 중 문서가 함께 바뀌지 않습니다.
- **실제 AI 연결 표시:** 키 설정 여부와 실제 응답 성공을 구분합니다. 선택한 모델의 호출 실패를 다른 모델의 성공이나 미리 작성한 응답으로 표시하지 않습니다. 예시 응답을 사용하는 경우에는 예시라는 표시가 남습니다.

구현 근거는 [자료실 컴포넌트](src/components/KnowledgeWorkbench.tsx), [AI 도움 API](src/app/api/knowledge/assist/route.ts), [작업 파이프라인](src/lib/pipeline.ts), [기관 설정](src/config/profiles.ts)에서 확인할 수 있습니다.

## RAG와 근거를 해석하는 방법

검색은 **BM25 계열 단어 점수와 한국어 문자 매칭을 결합한 서버 로컬 검색**입니다. 검색된 발췌문을 AI 입력에 넣는 RAG이며, 임베딩·벡터 데이터베이스·추가 학습을 했다고 표현하지 않습니다. 현재 고정 자료를 쓰는 데 별도 임베딩 API 키나 벡터 DB 계정은 필요하지 않습니다. 전체 원문 색인은 브라우저로 보내지 않습니다. [검색 구현](src/server/knowledge.ts)

| 근거 구분 | 용도 | 별도로 확인할 내용 |
|---|---|---|
| `KB-…` 입안 참고자료 | 제·개정 방식, 문장 정비, 부칙과 절차의 참고 기준 | 해당 기관·규정 종류에의 적용, 매뉴얼 이후 법령 개정 |
| `EV-…` 법령·사용자 원문 | 실제 검토 대상, 위임 조문, 상위법 전·후 원문 등 | 출처, 시행일, 조회일, 전문·별표 포함 범위, 사용자 입력 정확성 |
| 유사 기관 규정 | 조문 구성과 운영 사례 참고 | 그 기관의 권한·재정·위임 구조와 우리 기관의 차이 |
| 가상 기관 예시 | 앱 사용 흐름 연습 | 실제 기관의 사실·현행 법령으로 사용할 수 없음 |

자료의 **PDF 쪽**은 파일에서 여는 실제 페이지입니다. **책자 쪽**은 인쇄된 번호를 확인한 경우에만 별도로 표시합니다. 부록에서 번호가 다시 시작하는 자료도 있으므로 전체 문서에 단일 오프셋을 적용하지 않습니다.

AI 도움 API는 실제 검색 출처에 인용문이 존재하는지 대조하고, 존재하지 않는 인용·변경 제안을 제외합니다. 수치나 의무·조건 표현의 변화도 내용 변경 검토 대상으로 표시합니다. 그러나 **문구 존재 여부가 법적 결론의 타당성까지 증명하지는 않습니다.** 매뉴얼에 있는 문장만으로 개별 조례의 적법성이나 현행 위임 근거가 확정되지 않습니다. [응답 검증](src/server/knowledge-answer.ts)

## 제·개정 문서의 일관성을 만드는 구조

개정 작업은 원문을 구조화하고, AI가 변경 명세 `ChangeSpec`을 제안하고, 담당자가 이를 채택·수정하는 흐름입니다. 번호 이동, 인용 정비, 신·구조문대비표와 개정문은 같은 명세를 사용하는 엔진이 계산합니다. 이유·주요내용은 확정 내용과 맞춰 다시 작성하고 담당자 확인을 거칩니다. 작업 내용이 바뀌면 관련 검토 상태를 다시 확인하도록 합니다. [엔진](src/engine) · [검토 상태](src/lib/review.ts)

| 역할 | 처리 내용 |
|---|---|
| 원문 검토 | 조문 구조, 누락·부분 조회, 별표·서식 위험 확인 |
| 개정 계획 | 개정 의도를 변경 명세로 제안, 입안 자료와 실제 근거 참고 |
| 제정 체계·초안 | 목적과 근거에 맞는 조문 체계를 먼저 정하고 초안 작성 |
| 정합성 엔진 | 조·항·호와 인용 연결, 개정문·대비표 계산 |
| 점검·이유 작성 | 확인할 쟁점과 개정이유·주요내용 초안 |
| 담당자 | 근거와 의미 확인, 채택·수정, 문서 제출 여부 판단 |

다른 모델의 검토 의견을 비교하는 기능은 의견 차이를 보여 주는 보조 기능입니다. 모델 간 일치나 다수결을 적법성 판정으로 사용하지 않습니다. 이번 개선의 **5역할 분석·토론**은 개발·검증 과정의 역할 분담이며, 모든 버튼 클릭마다 5개 AI 모델이 회의하는 상시 실행 구조는 아닙니다.

## 결과물과 보관

일부개정 문서 세트에는 개정안, 신·구조문대비표, 개정이유·주요내용, 규정 종류에 맞는 예고·의견조회 문서, 입안 점검표, 개정 후 전문 참고본이 포함됩니다. 제정은 제정안, 제정이유·주요내용, 조문 체계표, 예고·의견조회 문서, 입안 점검표의 흐름입니다. 선택한 규정 종류·기관 설정·작업 상태에 따라 내용이 달라집니다. [문서 생성](src/lib/docs.ts)

DOCX, 실험적 HWPX, 한글에 붙여넣기용 복사를 제공합니다. HWPX의 파일 구조 검사와 실제 한컴 한글에서 열고 편집·저장하는 검사는 다릅니다. 최종 제출 파일은 사용하는 한글 환경에서 확인해야 합니다. 문서 ZIP에는 작업 보관파일, 근거 원문, 입안 참고자료 기록과 선택한 사용기록 CSV를 포함할 수 있습니다. 보관파일에는 API 키와 AI 연결 설정이 들어가지 않습니다. [문서 내보내기](src/lib/export.ts) · [보관파일](src/lib/project-transfer.ts)

기관 설정은 브라우저에 최대 20개, 기관 JSON은 256KB 이하, 규정 종류별 절차는 최대 25단계입니다. 기본 3개 예시 프로필은 복제해 새 기관을 만듭니다. 가져온 기관은 새 ID와 미확인 상태로 저장됩니다. 작업을 복원할 때 보관된 기관 설정은 해당 작업에서 사용하지만 새 브라우저의 기관 선택 목록에 자동 등록하지는 않습니다. 기관 선택 목록에도 필요하면 기관 JSON을 별도로 불러오세요.

## 로컬 실행과 기관 설치

Node.js 22 환경에서 실행합니다. 키 없이도 자료 검색·원본 내려받기·가상 예시 흐름을 사용할 수 있습니다.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

운영 전 검증과 빌드 명령은 다음과 같습니다. 명령이 있다는 것과 실제 해당 커밋에서 통과한 기록은 구분합니다.

```bash
npm test
npm run typecheck
npm run build
npm start
```

Docker 설치는 [Dockerfile](Dockerfile)의 standalone 구성을 사용합니다. 현재 저장소에 들어 있는 원본·검색 색인으로 운영할 때 Python·Poppler를 런타임에 설치할 필요는 없습니다. 참고자료를 교체해 색인을 다시 만들 때는 [RAG 갱신 절차](docs/RAG-ARCHITECTURE.md)를 따릅니다.

작업은 기본적으로 사용자의 브라우저 IndexedDB에 저장됩니다. 질문·본문·검색 발췌문은 선택한 AI 요청 시 앱 서버를 거쳐 해당 연결로 전달됩니다. 브라우저에서 기관 AI 주소를 고른 사실만으로 공개 Vercel 서버의 통신 경로가 내부망으로 바뀌지는 않습니다. 내부망 처리가 필요한 기관은 앱 서버와 모델 연결을 기관 환경에 설치하고 그 경로를 확인해야 합니다.

## 검증 범위와 현재 한계

복구 후 검색 개발 질의 60개에서 **자료를 지정하면 60/60, 전체 자료와 종류·관점 조건으로 검색하면 58/60**이 예상 원문을 상위 6개 안에서 찾았습니다. PDF 질의 56개는 예상 물리 페이지, HWPX 질의 4개는 요청서가 검색되는지를 측정했습니다. 학습·보정에 사용한 개발 질의이므로 독립 시험 정확도는 아닙니다. 따로 만든 8개 반례도 후속 보정에 사용했으므로 이제 미관측 평가 세트가 아닙니다. [실측 JSON](docs/validation/v04-retrieval-benchmark.json)

이 수치를 법률 정확도, 직원 업무효율, 대회 98점과 바꾸어 말하지 않습니다. **현재 버전의 테스트·운영 확인은 [v0.6 검증 기록](docs/VALIDATION-v0.6.md)의 실행 결과와 커밋·배포 식별자를 함께 확인하세요.** 짧은 모델 연결 시험과 실제 자료 근거 답변·문서 생성의 성공은 구분합니다. [v0.4 검증 기록](docs/VALIDATION-v0.4.md)과 [v0.3 검증 기록](docs/VALIDATION-v0.3.md)은 과거 버전의 기록입니다.

현재 적용 범위의 중요한 한계는 다음과 같습니다.

- 전체 PDF 페이지를 처리했어도 이미지 OCR, 표 셀의 관계와 복잡한 도표의 의미까지 완전히 복원한 것은 아닙니다.
- 수록 매뉴얼 이후의 법령 변경과 개별 기관의 권한·재정·절차는 공식 원문과 담당자 검토가 필요합니다.
- 유사 규정은 선택한 실제 원문 최대 4개를 비교하며 전국 규정을 모두 조사해 최적안을 평가하는 기능은 아닙니다. 5개년 통계는 표시한 검색어·지역·조회 완료 범위의 공포 기록입니다.
- 상위법 영향 검토의 자동 후보는 전·후에 같은 조 번호로 대응되는 본문을 중심으로 합니다. 신설·삭제·가지번호 이동·별표는 추가 검토가 필요합니다.
- 외부 편집기에서 수정한 DOCX/HWPX를 자동으로 원래 변경 명세에 되돌려 동기화하지 않습니다.
- 실제 직원의 비교 작업시간, 독립 법제 전문가의 최종 적법성 판정, 실제 한컴 한글에서의 최종 제출 검수는 별도 평가 대상입니다.
