## 실행 기록

### 로컬 통합 검사

- 1차 전체 자동 검사: 350/350 통과.
- 독립 검토에서 원문 첫 문장의 가지조문 인용을 머리말로 오인하는 결함을 재현했다. `referenceBody()`를 수정하고 본문 인용 보존·빈 AI 체계 거부에 관한 12개 회귀검사를 추가했다.
- 저장 확인 보강·원문 보존·문서 렌더 수정을 포함한 최종 자동 검사: **365/365 통과, 실패·보류 0개**. 운영 실측 후 일시적 429 재시도·자동 대체 연결·제목 표기 대응 보완을 추가한 최종 검사는 **381/381 통과**. TypeScript 검사와 Next.js 운영 빌드도 통과했다.
- 제정 5종·개정 6종 DOCX를 렌더링해 **15페이지**를 시각 확인했다. 점검표는 제정·개정 각 3쪽이며 나머지 9개 문서는 각각 1쪽이다. 표 행의 페이지 분리와 짧은 고아 줄을 수정했다.

### 공식 자치법규 API 실측

[실측 JSON](validation/v05-history-api.json)은 로컬 구현이 공식 API를 직접 호출한 기록이며 새 운영 엔드포인트 호출 기록과 구분한다.

- 검색어: 주민참여예산, 공포연도 2022~2026, 지역 코드 `6130000 / 5810000`.
- 약 2.145초에 현행·연혁 목록을 읽어 동일 공포를 합친 3개 기록을 확인했다. 2024·2025·2026년 각각 일부개정 1개이며 2022·2023년은 이 검색 범위에서 0개다.
- 조례 ID `2035792`의 2024년 `MST 1972513`, 2025년 `MST 2029315` 원문을 각각 31개 조문으로 읽었다. 유일한 조 제목 기준으로 동일 14행, 문자·번호 차이 5행, 대응 미확정 24행으로 표시했다. 반복 제목은 임의로 짝짓지 않았다.
- 현행판은 ID로 새로 조회했고, 조회 당시 `MST 2132533`, 공포 2026-06-16·시행 2026-07-01의 원문을 확인했다. 과거 제목·시행일을 현행판 정보로 재사용하지 않았다.

이 결과는 특정 주제·지역의 공포 기록이다. 전국 조례의 총수나 모든 변경 사항의 완전한 조사로 해석하지 않는다. 공식 API가 주는 목록·본문·부칙·별표 범위를 화면에서 따로 확인한다. [공식 목록 요청 변수](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinListGuide)

### 모델과 운영 배포

v0.5 배포 전 운영 설정 화면에서 GPT-OSS 120B·Groq 실제 응답 시험이 약 0.7초에 성공했고 반환 모델은 `openai/gpt-oss-120b`였다. 이 연결 시험을 v0.5의 전체 제정 성공으로 계산하지 않는다. 실제 v0.5 운영 검증은 다음과 같다.

- 첫 구현 배포: `6c6692ade4bc6c15fb152848e8e3311a0caae215`, Vercel `kevin-jeong/jomokjomok-law`, 배포 `8AQZDQ1bkiGmaY4tGdt7pZfapzBy`, 운영 `/api/diag` v0.5.0·icn1 일치. GitHub CI도 성공했다.
- Gemma를 명시적으로 골라 가상 한빛시 9개 조문 제정 체계를 19.0초에 생성했다. 본문 6개를 작성한 뒤 제공자가 HTTP 429를 반환했다. 이 단계는 26.4초였고 성공으로 표시하지 않았다.
- 페이지를 새로고침한 뒤 기존 6개 본문이 문자열까지 동일함을 확인했다. 남은 3개를 이어써 8.0초에 완성했고, 첫 6개는 바뀌지 않았다. 9개 모두 본문이 있는 상태에서만 점검·이유서·문서로 진행했다.
- 제정이유도 실제 Gemma로 생성하고, 가상 예고 정보와 검토 메모를 입력해 예고문·입안점검표를 개별 HWPX로 받았다. 제정 문서 5종의 HWPX/DOCX와 작업 백업이 든 ZIP도 실제 다운로드했다. [파일 검사](validation/v05-live-downloads.json)
- 서구·가평·강릉·거제의 현행 조례 4개를 비교했다. 전체 복사 결과 35,155자에 네 제목이 모두 포함됐다. 검색어를 위원회로 바꿔도 선택 4개가 유지됐고, 일괄 참고 후 새 작업 화면에서 4개 연결을 확인했다.
- 운영 API의 독립 실측은 [운영 조회 증거](validation/v05-history-production.json)에 기록했다. 현행·연혁 10개 범위가 모두 완료됐고 과거 두 버전과 현행판의 식별자가 일치했다.

### 운영에서 발견해 보완한 사항

1. **일시적 제공자 한도:** 429를 실제로 관찰한 뒤 제공자 대기 힌트를 지키는 제한된 재시도와 대기 표시를 추가했다. 자동 연결의 다른 제공자 전환도 보존하며, 명시 모델 선택과 같은 제공자 대기 지시는 유지한다. 한도 대기·취소·일일 한도·자동 전환은 fake-timer 회귀검사로 검증했다. 새 운영에서 자연 발생한 429의 자동 회복까지 관찰했다고 주장하지 않는다.
2. **제목의 가운뎃점 차이:** `위·해촉`과 `위ㆍ해촉`을 동일한 제목으로 대응시켜 실제 제8조의 연임 1회→2회 변경을 한 행에 표시한다. 반복 제목은 번호·제목·표기만 정규화한 본문까지 같고 양쪽에서 유일한 경우에만 대응한다. 운영 원문을 개선 로컬 함수로 비교한 결과 동일 20개·문자 차이 11개·미확정 0행이었으며, 11개에 단순 표기 차이도 포함된다. [재대조 증거](validation/v05-history-comparison-refinement.json)

마지막 보완 커밋과 그 운영 확인은 최종 배포 증거에 기록한다.

## 시간 제한과 저장의 실제 범위

`/api/llm`의 Vercel 요청 한도는 300초, 서버 제공자 호출·복구 예산은 270초, 브라우저 연결 한도는 310초다. 전체 9개 조문을 단일 54초 요청으로 처리하지 않고 최대 3개 조씩 나눠 작성한다. 10초 주기의 연결 확인 신호는 요청이 살아 있다는 뜻이며 실제 작성 완료율로 쓰지 않는다.

작업은 브라우저 IndexedDB에 저장한다. 페이지를 닫은 동안 AI를 계속 실행하는 서버 작업 큐는 아니며, 저장한 조문을 다음 접속에서 이어 쓴다. 사용자가 작성한 기존 본문은 재개 요청에서 제외한다. 의도적 취소를 예시 답안 성공으로 바꾸지 않는다. 미작성 조문이 남으면 점검·문서 단계를 완료로 표시하지 않는다.

자료실 전용 `/api/knowledge/assist`는 별도의 60초/54초 계약을 유지한다. 제공자 유료 API와 Vercel 실행 한도는 별개이며, 어느 모델의 모든 입력에서 응답 시간을 보장하는 변경은 아니다. [연결·시간 한도 안내](API-SETUP.md)

## 문서 검수의 경계

가상 기관·가상 시험 조례로 제정 5종과 개정 6종을 생성한다. HWPX는 XML·ZIP·참조·표 구조와 원문 텍스트를 검사하고, DOCX는 렌더링하여 쪽 나눔을 확인한다. 제공 매뉴얼에 완성 예고문 양식이 없는 부분은 필수 항목을 바탕으로 재구성했다고 표시한다.

검수 환경에는 한컴 한글이 없다. HWPX의 네이티브 열기·다시 저장·인쇄와 모든 한글 버전의 호환성을 검증했다고 주장하지 않는다. 생성 내용의 법률적 적합성과 실제 기관 서식 검토도 별도다. [상세 근거·수정 사항](research/v05-form-mapping.md)
