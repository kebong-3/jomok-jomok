# v0.5 문서 서식과 HWPX 검수 근거

## 적용 범위

사용자가 제공한 원본 PDF와 HWPX를 직접 확인했다. 원본 파일은 수정하지 않았다. 조목조목의 생성 문서는 원본 매뉴얼의 규격 또는 검토 기준을 적용한 **편집 가능한 초안**이며, 법제처가 배포한 완성 서식 원본과 구분한다.

| 문서·기능 | 확인한 원본 위치 | 반영 내용 | 적용 범위 |
|---|---|---|---|
| 자치법규 제정안·개정안·이유서 | 자치법규 입안 길라잡이 2026 PDF 416–419쪽, 인쇄 408–411쪽 | A4 세로, 상하 16mm·좌우 25mm, 머리말·꼬리말 12.7mm, 신명조 본문 14pt·제명 16pt·이유서 소제목 15pt, 본문 줄간격 230% | 조례·자치규칙에 기본 규격 적용. 기관별 결재 표지·의안번호 및 모든 내어쓰기 단계까지 동일하게 복제한 것은 아님 |
| 신·구조문대비표 | 같은 자료 PDF 420쪽, 인쇄 412쪽 | 현행·개정안 2열, 변경 부분 밑줄, 본문 14pt, 줄간격 180% | 문서 엔진의 확정 변경을 공통 모델에서 출력 |

| 행정규칙·내부규정 검토 기록 | 행정규칙 입안·심사 기준 2025 PDF 7, 18, 22, 36, 39, 41, 51쪽 | 법적 성격·위임·예고·시행/종전 부칙·등재·명확성·일몰 기준 | 중앙행정기관의 적용 규정을 모든 기관에 강제하지 않음. 내부규정은 기관 정관·내규와 대조 |

원본 체크리스트 자체도 모든 검토사항을 망라한 자료가 아님을 PDF 531쪽에서 밝힌다. 별도 분야의 세부 기준과 최신 상위법령 검토는 계속 필요하다.

## 서식 입력과 기록

- 공고번호, 공고일, 제출기한, 발령기관장, 접수기관·부서, 주소·전화·전자우편, 제출 방법, 전문 공개 위치를 한 번 입력하면 미리보기·HWPX·DOCX에 반영한다.
- 예고 의무나 기한을 자동으로 확정하지 않는다. 미입력 값은 작성란으로 남긴다. 기한이 공고일보다 빠르면 화면에서 표시한다.
- 이유서의 예산조치·비용추계, 관계부서 협의, 그 밖의 참고사항을 편집할 수 있다.
- 12항 검토 입력은 문서 받기의 추가 필수 절차가 아니다. 미확인 항목은 그대로 기록한다.
- 검토 상태는 해당 초안 지문과 함께 보관한다. 조문·변경내용이 바뀌면 이전 검토 결과에 재확인 표시가 붙는다.
- 입력값과 검토 메모는 `작업백업.jomok.json`에 허용 필드만 보관하며, 가져오기에서 길이·날짜·중복 항목을 검증한다.
- 개별 문서 HWPX·DOCX 받기 버튼과 기존 전체 문서 세트 ZIP을 함께 제공한다. ZIP의 `서식기준.txt`에 적용한 원본 쪽수와 재구성 범위를 적는다.

## HWPX 수정 사항

1. `hh:charPr`에서 굵게 속성을 글꼴·비율·자간·상대크기·위치 속성 뒤에 둔다. 제공된 공식 HWPX의 속성 순서와 맞췄다.
2. 텍스트 내부 개행을 `hp:lineBreak`로 출력한다. 단순 XML 텍스트 개행에 의존하지 않는다.
3. XML 1.0에서 허용되지 않는 제어문자와 고립 UTF-16 서로게이트를 제거하고, 한글·정상 이모지·특수문자를 보존한다.
4. 제목에 `$&` 또는 `$1` 등이 들어가도 정규식 치환 문법으로 해석되지 않도록 콜백 치환을 쓴다.
5. 표 너비의 나머지를 마지막 열에 더해 본문 너비와 일치시키고, 셀 수·열 수 불일치는 생성 전에 거부한다. 표 ID는 문서 안에서 중복되지 않도록 순차 부여한다.
6. `mimetype`을 ZIP 첫 항목·무압축으로 보관한다. 매니페스트와 읽기 순서를 보존하며, 헤더는 본문 읽기 순서의 비선형 항목으로 표시한다.
7. 모든 XML의 정형성, 필수 파일, 본문의 글자·문단·스타일·테두리 참조, 매니페스트와 파일 존재, 표 행·열 개수를 파일 생성 전에 검사한다.
8. 기존 템플릿에 남아 있던 원 작성일 메타데이터를 제거한다.

공식 설명: [한컴 HWPX 포맷 구조](https://tech.hancom.com/hwpxformat/), [한컴 개발자 포럼의 문단·줄 나눔 안내](https://forum.developer.hancom.com/t/owpml-hp-t/1685), [한컴 OWPML 모델](https://github.com/hancom-io/hwpx-owpml-model).

## 출력 검수 방법과 한계

`scripts/verify_forms.ts`는 **가상 한빛시의 서식 시험용 조례**로 제정 5종·개정 6종의 DOCX/HWPX를 생성한다. 주민 정보나 실제 기관의 비공개 문서를 사용하지 않는다. 실행 예:

```sh
node node_modules/vite-node/vite-node.mjs --config vitest.config.ts scripts/verify_forms.ts /tmp/jomokjomok-forms
```

자동 회귀검사는 문서 규격, 개행, 특수문자, 잘못된 서식 참조, 12항 포함, 입력값 반영, 보관파일 복원을 확인한다. 별도 검수에서는 ZIP CRC 검사와 독립 XML 파서(lxml)로 패키지·표·글자 속성 순서·원문 모델과 텍스트 일치를 확인하고, DOCX를 LibreOffice로 렌더링해 모든 페이지를 시각 확인한다.

2026년 10월 25일 검수에서는 HWPX 11개 모두 독립 구조·텍스트 검사를 통과했다. DOCX 11종 총 15쪽(제정·개정 점검표 각 3쪽, 나머지 9종 각 1쪽)을 페이지별로 확인했다. 첫 렌더에서 확인한 고아 줄과 페이지 경계에서 분리된 점검표 항목은 행높이·행 분할 설정을 고친 뒤 다시 렌더해 해결했다. 상세 결과와 파일 해시는 `docs/validation/v05-documents.json`, 재현 가능한 가상 문서 묶음은 `docs/validation/v05-form-fixtures.zip`에 있다. 페이지 수는 가상 검수 자료 및 해당 글꼴 환경에 대한 결과다.

검수 환경에는 신명조와 함초롬 글꼴이 설치되어 있지 않아 공식 Noto Serif CJK KR/Noto Sans CJK KR 글꼴을 렌더링 대체 글꼴로 사용한다. 생성 파일에는 매뉴얼의 신명조 지정이 유지되며, 실제 한글에서는 기관 PC에 설치된 글꼴을 확인해야 한다. DOCX는 HWP의 글자크기×줄간격을 포인트 행높이로 표현해 대체 글꼴 메트릭 때문에 짧은 문서의 마지막 한두 줄만 다음 장으로 밀리는 문제를 줄였다.

**이 환경에는 한컴 한글 실행기가 없다.** 검수는 전체 KS X 6101 스키마 인증이나 한글 네이티브 열기·다시 저장·인쇄 시험을 대신하지 않는다. 한글 버전별 최종 편집·인쇄 결과와 기관의 공식 공고·결재 서식 적합성은 기관 PC에서 확인해야 한다. 생성 파일의 구조 검사 성공과 법적 내용의 적법성을 동일시하지 않는다.
