# v0.7 조목이 화면 독립 검수

검수일: 2026-10-26. 검수 대상은 v0.7 작업 중인 공유 코드이며, 이 문서 작성 자체가 운영 배포 확인을 뜻하지 않는다.

**정적 검수에서 발견한 네 가지 문제의 수정 코드를 모두 재확인했다.** 말풍선 확대 시 중첩 위험도 일반 문서 흐름으로 바꾸어 보완했다. 이 검수 범위에서 미해결로 남긴 코드 수정사항은 없으며, 실제 운영 브라우저의 배치·상호작용 확인은 별도로 남는다.

## 범위와 방법

홈의 큰 조목이, 여섯 표정과 움직임 제어, 시작 화면 및 작업 단계의 캐릭터 상태를 독립적으로 읽었다. SVG 구조, CSS 우선순위와 화면 폭 대응, React effect의 정리, 버튼의 접근 가능한 이름과 상태, 공식 문서 출력과의 격리를 중심으로 확인했다.

이 검수자는 앱 코드를 수정하지 않고 발견사항을 해당 담당자에게 전달했다. 브라우저 조작, 스크린리더 실기기 확인, 추가 자동 테스트, 전체 빌드, 원격 저장소 및 운영 배포는 수행하지 않았다. 전체 기능 검사와 실제 운영 화면 검증은 통합 담당자가 수행하는 별도 검증이다.

## 코드에서 확인한 동작

### 표정과 동작

홈에서 선택하는 인사·미소·활짝 웃음·생각·응원·다정함은 단순한 이름 변경이 아니다. SVG의 눈·입·팔·눈썹·생각 풍선·하트·색종이와 CSS 동작을 실제로 다르게 렌더링한다. 홈의 표정 선택은 자동 전환을 끄고 선택한 표정을 유지한다. 작업 화면의 기본 `motion="once"`는 유한 횟수이고, 홈에서만 반복 동작을 요청한다.

SVG에는 여러 인스턴스 사이에서 충돌할 수 있는 고정 `id` 참조가 없다. 홈의 설명 가능한 캐릭터는 `role="img"`와 표정별 이름을 제공한다. 주변 안내 문장으로 의미가 전달되는 작업 화면의 장식 캐릭터는 접근성 트리에서 숨긴다.

근거: [캐릭터 SVG](../../src/components/Jomoki.tsx), [캐릭터 동작 CSS](../../src/components/Jomoki.module.css), [홈 표정 제어](../../src/components/JomokiShowcase.tsx).

### React effect와 움직임 제어

자동 전환 effect는 갱신 전·컴포넌트 해제 시 interval을 정리하고 `visibilitychange` listener를 제거한다. 숨겨진 탭에서는 interval을 만들지 않고 캐릭터에도 `motion="none"`을 전달한다. 동작 정지 시 표정 자동 전환과 CSS 동작을 함께 멈춘다.

기기의 `prefers-reduced-motion`을 읽는 effect는 변화 listener를 해제한다. CSS도 독립적으로 동작 줄이기를 적용하므로 React effect가 실행되기 전에도 반복 애니메이션이 강제되지 않는다. 해당 설정을 켜면 자동 전환을 끄고, 설정을 해제한 뒤 사용자가 다시 켤 수 있게 한다. 표정 버튼은 줄이기 설정 중에도 사용할 수 있다.

표정 버튼은 기본 `button` 요소이며 선택 상태에 `aria-pressed`를 사용한다. 키보드 포커스 테두리도 있다. 홈의 자동으로 바뀌는 말풍선은 `aria-live="off"`로 두어 모든 전환을 지속적으로 읽게 만들지 않는다.

근거: [홈 제어 effect](../../src/components/JomokiShowcase.tsx), [홈 제어 CSS](../../src/components/JomokiShowcase.module.css), [공통 움직임 줄이기 규칙](../../src/app/globals.css).

### 좁은 화면 대응

홈은 700px 이하에서 한 열로 배치하고 430px 이하에서는 시작 버튼도 한 열로 배치한다. 캐릭터에 `max-width: 100%`가 있고 표정 버튼 그리드는 `minmax(0, 1fr)`을 사용한다. 360px 이하에서는 장식 메모를 숨기고, 자동 전환·동작 제어 버튼은 줄바꿈을 허용한다. 다음 행동 안내는 캐릭터를 단계적으로 줄이고 본문에 긴 단어 줄바꿈을 허용한다.

처음에는 홈 말풍선이 절대 위치여서 글자 확대 시 캐릭터를 가릴 위험을 전달했다. 통합 담당자가 `.stage`를 세로 flex 배치로 바꾸고 말풍선을 `position: relative; width: 100%`의 일반 문서 흐름에 넣은 최종 코드를 재확인했다. 문구가 여러 줄이 되면 캐릭터가 아래로 밀리는 구조다.

이것은 CSS 대응 규칙을 확인한 결과다. 모든 글꼴·확대 배율에서 시각적으로 맞는다고 보장한 결과는 아니다. 320px 폭과 글자 확대의 실제 배치는 운영 브라우저에서 확인할 대상으로 전달했다.

근거: [홈 배치](../../src/app/Home.module.css), [표정 제어 반응형 규칙](../../src/components/JomokiShowcase.module.css), [다음 행동 배치](../../src/components/work/NextSteps.module.css).

### 공식 문서와 캐릭터의 격리

HWPX·DOCX 생성과 클립보드용 HTML은 화면 DOM을 복사하지 않고 `DocModel`의 제목·문단·표를 사용한다. 조목이 컴포넌트는 이 직렬화 경로에 들어가지 않는다. 파일 준비 완료의 캐릭터는 다운로드 안내 영역에만 있다.

브라우저 인쇄에서는 조목이와 홈 쇼케이스의 `@media print` 숨김, 다음 행동의 `no-print`, 작업 검토 패널의 `no-print`, 문서 탭에서 `printDocument` 외의 자식을 숨기는 규칙이 함께 작동한다. 문서 본문용 `PaperDoc`에는 캐릭터를 렌더링하는 코드가 없다.

## 통합 담당자가 확인할 시각적 경계

- 홈 320px 폭과 확대 상태에서 말풍선·캐릭터·표정 선택 영역이 겹치거나 가로 스크롤을 만들지 않는지 확인한다.
- 표정을 직접 고른 뒤 자동 전환이 멈추는지, 동작 정지 뒤 CSS 동작과 전환이 함께 멈추는지 확인한다.
- 기기 움직임 줄이기 설정에서 여섯 표정을 수동 선택할 수 있고 자동 반복이 생기지 않는지 확인한다.
- 조문 반영 직후와 이후 수동 수정 상태가 서로 다른 문구·표정으로 안내되는지 확인한다.

위 항목의 운영 실측은 통합 검증 기록에 남긴다. 이 정적 검수 문서를 실제 브라우저·스크린리더 또는 한컴 프로그램의 호환성 검증으로 인용하지 않는다.
