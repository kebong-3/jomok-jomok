# v0.8 쟁점별 검색과 검토 범위 기록

검토일: 2026-10-27. 자료 버전 `moleg-2026-10-24-v1` 유지.

## 문제와 변경

이전 자료실 검토는 질문과 초안 앞 700자로 검색했다. AI에는 입력한 본문 전체를 전달했지만, 끝에 있는 위원 임기·경과조치나 별지 서식에 맞는 자료가 검색되지 않을 수 있었다. 여러 쟁점을 한 번에 요청했을 때 한 주제의 발췌문이 입력 예산을 차지하는 문제도 있었다.

`src/server/knowledge-review.ts`는 질문과 입력 본문 전체(최대 12,000자)에서 검색 단서를 찾는다. 권한·위임, 부칙, 개정 형식, 문장, 의견제시 요청, 예고·절차의 여섯 관점 중 실제 단서가 있는 관점을 검색한다. 질문 자체의 검색 결과도 별도로 유지한다. 질문이나 입력 본문이 명령문을 포함하더라도 실행하지 않고 문자열 자료로 처리한다.

각 검색의 첫 자료를 순환 선택한 뒤 추가 자료를 보강한다. 같은 문서의 같은 PDF 물리 페이지는 중복 선택하지 않는다. 최대 6개, 본문 합계 5,500자 한도를 유지하고, 원문 발췌문을 잘라 지문·인용 대조를 깨뜨리지 않는다. 일곱 검색 관점의 근거를 모두 넣을 수 없으면 제외 내역이 남는다. 모든 쟁점을 회수했다고 주장하지 않는다.

## 범위 기록과 업무상 해석

`KnowledgeRecord.coverage`는 다음을 보존한다.

- 입력 본문 글자 수와 검색 단서를 탐지한 글자 수
- 검토 요청에 넣은 조문·부칙·별표 등 본문 단위
- 질문·쟁점별 검색어, 실제 참고 입력에 포함한 KB ID
- 관련 발췌문 미발견과 입력 예산으로 제외된 관점의 구분
- 실제 발췌문 분량과 한도

자료실과 작업 내 검토는 이 기록을 결과 위에 보여 준다. 상세 조문 범위는 접어 두고, 미발견·예산 제외는 구체적인 상태 문구와 색을 함께 표시한다. 검토문 복사·TXT 내려받기, 작업 보관파일에도 같은 범위가 유지된다. 이전 범위 없는 기록은 호환하되 범위 미기록이라고 표시한다.

이 기록은 **검색과 입력의 범위**다. 조문별 법제 검토 완료, 적법성 승인 또는 현행 법령 확인이 아니다. AI 요청 실패 시에도 검색 자료는 남으므로, 실제 AI 응답 성공 상태와 입력 준비 기록을 분리해 읽어야 한다. 키워드 탐지·검색 순위는 관련성 후보이며 인용이 법적 결론을 뒷받침하는지 의미적으로 증명하지 않는다.

서버가 선택한 출처만 답변 검증에 사용하고, 기존의 인용문·변경 전 문장 대조와 수치·조건 변경 감지는 유지한다. 프롬프트는 미발견·예산 제외를 적법·해당 없음으로 바꾸지 않고 추가 확인에 남기도록 한다. 가짜 SYSTEM, JSON, XML 닫기 태그 같은 문서 안 지시는 상위 지시가 아니다. 이 지시문 방어만으로 모든 모델의 공격 내성을 보증하지는 않는다.

## 다섯 원본과 대조한 사항

PDF 원본을 `pypdf`로 열어 해당 쪽의 텍스트와 코퍼스를 대조했고, 요청서 원본 HWPX의 `Contents/section0.xml` 항목을 확인했다. 전체 1,997쪽 정독이나 모든 도표의 시각 검토를 수행했다고 주장하지 않는다.

| 원본 | 직접 대조한 PDF 물리 쪽 | 검색·업무 방식에 반영한 구분 |
| --- | --- | --- |
| 자치법규 입안 길라잡이 2026 | 26, 362–363 | 포괄적 시행규칙 문구와 구체적 위임의 차이, 변경 내용별 적용 관계와 예외를 별도 쟁점으로 찾음 |
| 법령 입안·심사 기준 | 777–778 | 전부개정·폐지와 종전 부칙을 형식·부칙 양쪽 검색 단서로 다룸 |
| 행정규칙 입안·심사 기준 2025 | 40–42 | 중앙행정기관 적용 대상·제외, 존속기한·재검토기한 차이를 단일 결론으로 합치지 않음 |
| 알기 쉬운 법령 정비기준 2026 | 121–122, 157 | 접속어·수량 표현 정비의 의미 변화가 별도 쟁점임을 유지 |
| 자치법규 의견제시 요청서 | HWPX 고정 PDF 쪽수 없음 | 요청 요건과 실제 입력 사실을 구분하고 서식의 예시 체크를 실사용 사실로 복제하지 않음 |

코퍼스·원본 지문·manifest·판본은 변경하지 않았다. 현행 법령을 조회한 기록으로 과장하지 않는다.

## 시험과 남은 한계

새 `tests/knowledge-coverage.test.ts`는 긴 도입부 뒤 마지막 조문의 쟁점, 복합 질문의 예산·중복 페이지, 무관한 질문의 자료 부족, 미발견/예산 제외 분리, 가지조문 범위 표시, 변조된 범위 기록 거부, 범위 없는 구버전 기록 호환을 검증한다. 프롬프트 지시문 계약도 확인하지만 실제 모델 공격 시험 또는 법리 정확도 평가로 세지 않는다.

기존 자료실 API의 질문·본문 길이 제한, 원문 전체 전달, 허위 인용 제거, 사용자 주입 출처 무시, AI 실패 시 자료 보존 검사는 유지한다. 최종 통합 시험 결과는 루트의 버전 검증 기록을 기준으로 한다.

이 변경은 자료실 `knowledge_assist`와 작업 내 자료 검토 경로에 적용된다. 일반 제·개정 AI 역할의 `retrieveForRole`은 기존의 의도·목적과 역할 기준 보강을 유지한다. 그 경로까지 쟁점별 검토 완료를 표시하지 않는다. 검색 조각의 인접 페이지 예외를 항상 회수하거나 모든 법리 쟁점을 탐지하는 기능, 여러 번의 검토를 합친 법리 승인 체계, 독립 법제 전문가의 정답 평가는 포함하지 않는다.
