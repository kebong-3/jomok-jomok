## 1. 평가의 기준

사용자가 제시한 필수 기능은 두 흐름이다.

- 제정 목적과 상위법 위임 조항 → 조문 체계 → 담당자 확정 → 조문 초안 → 제정이유 및 관련 문서 세트.
- 현행 원문과 개정 의도 → 적용 가능한 변경 제안 → 담당자 수락 → 개정문·부칙·신구조문대비표 → 연결 조문·별표·서식과 오류 검토.

자료 6개를 앱에 넣거나 챗봇을 추가한 사실만으로 이 흐름의 완성도가 올라갔다고 평가하지 않는다. 실제 작업에서 참고 근거를 찾고, 원문과 변경 후 내용이 일치하며, 결과 파일과 검토 기록을 다른 기기에서도 이어갈 수 있어야 한다. 실제 직원 실증과 법무 검토는 자동 테스트와 별도 증거다.

## 2. 세 전문 분석을 검토한 결과

검토한 문서는 `v04-ordinance-review.md`, `v04-drafting-review.md`, `v04-language-review.md`다. 각 역할이 원문 전체 구조를 조사하고 확인한 쪽수를 바탕으로 다음 위험을 우선순위로 삼았다.

1. **입안 참고자료와 법적 수권 근거 혼동**: KB 자료를 찾았다는 사실은 현재 시행 법령·위임문을 조회했다는 사실이 아니다. 두 종류의 근거를 프로젝트와 화면에서 분리한다.
2. **예외 누락**: 짧은 체크리스트만 상위 검색되면 중앙행정기관 재검토기한을 모든 지자체 내부규정에 적용하거나 개정량 기준을 절대 규칙으로 오인할 수 있다. 본문·적용대상·예외 회수를 함께 확인한다.
3. **쪽수 오인**: PDF 물리 페이지와 책자 쪽수를 구분하고 알법 부록의 쪽수 재시작을 반영한다. HWPX에는 가짜 PDF 쪽수를 붙이지 않는다.
4. **문장 정비의 내용 변경**: 원문의 개정 전·후 예시에는 수치·조건·권리의무 변경도 섞여 있다. 쉬운 표현 제안이 의미를 보존한다고 자동 판정해서는 안 된다.
5. **원문 범위 오인**: 법령 API가 본문 조문을 가져왔다고 부칙·별표·서식이나 공포 후 미시행 개정을 전부 읽은 것으로 표시하지 않는다.
6. **참고 사례의 권한 오인**: 타 기관 조례가 존재한다는 사실만으로 우리 기관에 같은 조항을 둘 수 있는 것은 아니다. 유사 규정 비교에 적용대상·기관·위임 근거 확인을 남긴다.

## 3. 실제 토론과 결정

### 검색 성능과 법적 설명 정확성을 분리해야 한다

검토 역할은 검색 엔지니어에게 “6개 결과 안에 관련 페이지가 들어왔다는 지표만으로, 적용 예외를 포함한 법리 설명까지 정확하다고 주장하면 안 된다”고 이견을 제시했다. 재검토기한·전부개정·적용례가 대표 반례다.

검색 엔지니어는 직접 의미어·검색어 포괄률을 검토하고, 자동 RAG에서 주요 결과와 같은 절의 인접 예외를 보강하며, 관련 페이지 회수율과 실제 AI 설명의 법리 검토를 별도로 보고하기로 했다. 전체 PDF의 텍스트 추출과 그림·표 구조의 완전 복원도 구분하기로 했다. 같은 페이지 머리말만으로 다른 절을 섞는 위험도 확인해 인접 보강의 절 구분을 보수적으로 제한하기로 했다.

### 검증된 인용 문자열이 곧 검증된 법적 결론은 아니다

주 담당자에게 실제 인용이 존재해도 그 인용이 해당 사안의 결론을 뒷받침하는지는 별도 판단이라고 지적했다. 주 담당자는 KB 검색 기록을 EV 법령 근거와 합치지 않고 별도로 보존하며, 확인되지 않은 위임을 확정한 것으로 표시하지 않기로 했다. 인용 ID·정확 인용문 검증은 없는 출처를 막는 장치이며 사안의 적법성 인증이 아니다.

### 수치·조건 변화 탐지의 순서 문제

개발 중 `knowledge-answer.ts`의 수치·논리어 비교에서 `sort()`를 사용한 것을 확인했다. “10명 이상 30명 이하”를 “30명 이상 10명 이하”로 바꾸면 숫자 집합은 같지만 의미는 달라진다. 순서 보존 비교와 “할 수 없다”, “해서는 아니 된다”, “정당한 사유 없이” 같은 부정 의무·예외 표현 보강을 요청했고 주 담당자가 반영하겠다고 회신했다. 최종 게이트에서 해당 반례 테스트 결과를 확인해야 한다.

### 보관파일의 해시는 진본 인증과 다르다

초기 보관파일 검증은 KB 발췌문의 자체 해시와 자료 메타데이터를 확인하지만, 발췌문과 해시를 함께 다시 계산한 경우 원본 코퍼스와의 일치까지 입증하지 못한다. 원본 코퍼스에서 생성한 인용 ID·쪽수·내용 해시 색인과 대조하거나, 대조 전 참고자료임을 구분하도록 제안했다. 주 담당자는 원본 코퍼스의 인용 ID에 대응하는 정규 튜플 SHA-256 색인을 생성하고 복원 시 본문·쪽수·항목을 대조하는 수정 및 전체 보관파일을 다시 서명한 위조 반례 테스트를 구현하겠다고 회신했다. 최종 통합 게이트에서 복원된 구현까지 확인한다.

### 기관 설정의 실제 범위

최초 검토 시점 `profiles.ts`는 3개 고정 프로필이었다. “코드 수정 없이 기관 이식”이라는 표현을 그대로 쓰려면 기관명·장명·법무부서·연락처·예고 정보 등을 사용자가 설정하고 보관할 수 있어야 한다. 그렇지 않으면 지원 범위를 고정 프로필 선택으로 명시해야 한다. 이 항목은 확산 용이성에 직접 연결된다. 주 담당자가 제2 역할에 실제 기관 프로필 편집·보관 구현을 후속 배정했다. 구현 후 새 기관으로 제정 문서·입법예고문을 만들고 백업·복원하는 확인이 필요하다.

## 4. 이번 역할이 구현한 유사 규정 검색·비교

### 기능 계약

`SimilarRules`는 독립 컴포넌트이며 `initialQuery`, `initialKind`, 선택적 `onUseReference` 콜백을 받는다. 기본 검색 종류는 `ordin`이다. 콜백 자료는 `SimilarRuleReference = { hit, doc, meta }`다. 기존 공식 검색·본문 조회 API를 재사용하며 새 검색 서비스·추가 AI 키가 필요하지 않다. `@/server/law`는 타입만 가져오므로 브라우저에 서버 구현을 묶지 않는다.

- 자치법규, 행정규칙, 법령을 선택하고 주제 또는 규정명으로 검색한다.
- 알고 있는 공식 기관코드를 선택적으로 입력할 수 있다. 기관명을 임의의 코드로 바꾸지 않는다.
- 실제 원문을 최대 2개 선택한다. 선택한 종류·식별자·제목과 본문 응답을 다시 대조한다.
- 시행예정·잘못된 날짜·검색 후 바뀐 시행일·중복 조 번호·다른 규정 응답을 비교에 추가하지 않는다. 시행일이 제공되지 않으면 미확인으로 표시한다.
- 공식 조회가 실패해 저장본이 돌아오면 현재 타 기관의 규정인 것처럼 비교하지 않고 원인을 표시한다.
- 서로 다른 규정의 **조 번호가 같다는 이유로 대응시키지 않는다**. 각 규정에서 한 번만 나타나는 동일 조 제목을 기준으로 나란히 배치한다.
- 같은 제목도 실질적 동일성을 의미하지 않는다고 밝힌다. 제목이 없거나 여러 번 나오면 대응을 확정하지 않는다.
- 실제 본문, 기관, 시행일, 조회시각, 공식 출처, 조회 범위를 표시하고 복사할 수 있다.
- 부칙·별표·서식·미시행 개정은 별도 공식 원문 확인 대상이다.
- 입력어·검색대상·기관 필터를 바꾸면 이전 검색과 비교를 지우고 진행 중 요청을 취소한다. 늦은 응답을 새 검색의 결과로 표시하지 않는다.
- 반환된 임의 주소를 그대로 링크하지 않는다. 공식 HTTPS 도메인과 비밀값 없는 주소임을 확인한 뒤 공개 원문 주소를 구성한다.

## 5. 검색 엔지니어의 개발 질의와 별도로 한 독립 검색 감사

| 반수 이상을 과반수로 간단히 바꿔도 같은 뜻인가요? | 알법 PDF 157이 1위. 검색된 예시를 그대로 동일 의미라고 답하지 않는지 실제 AI의 수치·의결 조건 검토가 필요하다. |
| 중앙부처의 재검토기한 표준 문구를 우리 공단 내부 회계규정에 그대로 넣어야 하나요? | 행정규칙 PDF 144·41·40·42가 상위 4개. 적용대상과 제외 규정이 회수된다. 공단에 대한 자동 적용을 단정하지 않아야 한다. |
| 법률에서 조례에 맡긴 사항을 다시 구청장 고시로 정하도록 해도 되는지 검토하고 싶어요. | 자치법규 PDF 319 사무 재위임이 1위. 입법 위임과 사무 위임을 혼동할 위험이 있어 검색 엔지니어에게 개선 요청했다. |
| 2027년 새 법령의 최신 개정 공포 번호를 알려 주세요. | 공포·시행 전 개정문 작성 자료가 검색된다. 매뉴얼은 이 질문의 최신 사실을 알려 주지 않으므로 실제 AI가 현행 조회가 필요함을 밝혀야 한다. |
| 제3조부터 제5조까지라고 쓰면 사이에 새로 넣은 제4조의2까지 포함되나요? | 무관한 조 번호 예시가 상위에 오르고 직접 근거인 자치법규 PDF 440(책자 432쪽) 각주 298이 상위 6개에 없다. 검색 실패 반례로 전달했다. |

마지막 질의는 조 번호·숫자에 묻힌 의미어와 가지조문 인용·준용 문맥 회수의 문제를 드러낸다. 검색 담당자는 매뉴얼 원리 질문의 예시 조 번호를 제거하고 가지조문 형식을 개념어로 보강했으며, 입법 위임과 사무 위임의 문맥을 구분했다. 페이지나 정답을 직접 지정하는 처리가 아니다.

소실 전 보정 후 담당자 보고에 따르면 가지조문 질문은 자치법규 PDF 440이 1위, 입법 재위임 질문은 PDF 24가 1위·23이 4위였고 사무 재위임 PDF 319는 상위 6건에서 빠졌다. 원문 없는 위법 질문과 2027년 최신 공포 질문에는 여전히 참고 매뉴얼이 검색되므로 답변 타당성·최신성 검증은 별도로 필요하다.

이 결과를 반영해 검색을 보정했으므로 이 8개는 이후 **개발 반례 집합**이다. 첫 관찰과 보정 후 결과를 나누어 남기며, 같은 질의의 재통과를 독립 일반화 성능으로 발표하지 않는다. 60개 개발 질의의 소실 전 마지막 보고는 문서 지정 60/60·전체 58/60이었으나, 복원 시 재추출 문단 경계가 달라져 현재 코퍼스에서 재측정 중이다. 본문 문자열 검증·관련 페이지 회수·사안별 법리 정확성은 서로 다른 검증이다.

## 6. 최종 배포 전 수용 게이트

| 게이트 | 관찰해야 할 결과 | 실패로 볼 상황 |
|---|---|---|
| 제정 실제 실행 | 사용자 목적·제목·기관 유지, 체계→본문→이유서, 실제 모델·참고자료 기록, 결과 파일 | 가상 기관명으로 바뀜, 빈 본문을 완성으로 표시, 예시 응답을 실제 AI로 표시 |
| 개정 실제 실행 | 사용자 수락 변경만 개정안·대비표·개정 후 전문에 동일 반영 | 미수락 변경 반영, 원문에 없는 find 적용, 문서 간 숫자 불일치 |
| 인용·영향 | 항 삽입·삭제·가지번호와 별표·서식 인용을 확인하고 수정/보류 상태 보존 | 자동 정정할 수 없는 삭제 인용을 확정 수정하거나 누락을 숨김 |
| RAG 실제 실행 | AI 응답에 해당 검색 ID·원문 인용·검증된 페이지 제공, 예외/적용 범위 표시 | 없는 인용/페이지, 목차만으로 확정 답변, 매뉴얼을 현행 법령이라고 표시 |
| AI 장애 | 검색 결과·원문 다운로드 유지, 실제 실패 원인 표시 | AI 실패를 규칙 답변이나 다른 모델 성공으로 숨김 |
| 자료 6개 다운로드 | 원본 파일 바이트·SHA-256 유지, PDF 열림/HWPX CRC 확인 | 파일 일부만 배포, 안내문 해시를 공식기관 공표 해시로 표시 |
| 유사 규정 | 공식 조회 결과 2개 비교, 조 제목 기반 대응, 출처·현재성 범위 확인 | 다른 조 제목을 같은 조 번호로 연결, 조회 실패를 검색 0건으로만 표시 |
| 백업·복원 | AI 입력 참고자료·원문·검토 상태 보존, API 키 제외, 원본 대조 | 저장했다는 메시지만 있고 실제 복원 안 됨, 참고자료 해시 불일치 무시 |
| 모델 이식 | 최소 두 어댑터의 요청 형식/실패 처리 검증, 기관 서버 URL 허용 정책 | 임의 서버로 공용 키 전달, 잘못된 선택을 다른 제공자로 조용히 대체 |
| 기관 이식 | 새 기관명·기관장·법무부서·연락처·예고 정보로 문서 생성과 복원 | 화면 설정만 바뀌고 문서에는 가상기관·이전 기관 정보가 남음 |
| 시각·사용성 | 데스크톱·좁은 화면에서 검색→검토→문서 흐름 수행, 오래된 답변 제거 | 가로 넘침, 현재 입력과 다른 이전 결과가 그대로 남음 |

자동 검증과 별도로 남는 작업은 실제 직원의 같은 안건 전후 비교 실증, 법무 담당의 대표 안건 검토, 실제 한글 프로그램 열기·인쇄, 기관별 공식 절차·배포 환경 승인이다. 이 작업을 수행하지 않았다면 완료 수치나 공식 98점으로 환산하지 않는다.
