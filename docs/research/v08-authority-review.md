# v0.8 조문별 권한·근거 검토

검토일: 2026-10-27. 역할 1: 입법 권한·조문별 근거. 5종 전체 정독이 아니라 아래 쟁점 원문과 기존 구현을 대조했다.

## 자료와 실제 반영

| 확인한 자료 | 반영한 판단 순서 |
| --- | --- |
| 자치법규 입안 길라잡이 PDF 21–25쪽 / 본문 13–17쪽 | 사무 성격, 입안 주체와 규정 형식을 구분하여 담당자가 기록한다. 조례·규칙의 구분을 키워드만으로 확정하지 않는다. |
| 같은 자료 PDF 26쪽 / 본문 18쪽 | 포괄적 시행규칙 문구 발견 시 맡길 사항·범위와 조례에 남길 기준을 묻는다. 단순 집행 문구 자체를 위법으로 단정하거나 새로운 주민 의무의 근거로 자동 인정하지 않는다. |
| 같은 자료 PDF 68쪽 / 본문 60쪽 | 허가·등록·신고·의무·제재 표현은 먼저 살펴볼 후보로만 탐지한다. 주민에 대한 새로운 부담인지, 직원 내부 업무인지는 담당자가 분리한다. |
| 같은 자료 PDF 75쪽 / 본문 67쪽 | 근거 법령의 명칭과 원문·위임 경로·대상·범위 대조를 분리한다. 근거를 검색했다는 사실만으로 권한 확인이나 적법성 승인을 표시하지 않는다. |

PDF 26·68·75쪽은 원본 PDF에서 직접 텍스트를 추출하여 검색 코퍼스와 대조했다. 나머지 관련 페이지는 배포 코퍼스 발췌문을 확인했다. 매뉴얼 판본의 수록 기준과 현재 개별 법령의 효력은 구분한다.

## 구현

- 현재 초안의 각 조문에 적용 대상, 자치/위임/내부 사무, 주민 권리·의무 영향, 연결 EV, 원문 인용, 허용 범위, 재위임·집행사항, 담당자 판단을 저장한다.
- 새로운 주민 부담이 없는 자치사무에는 개별 위임 조문 입력을 일률적으로 강제하지 않는다. 내부 직원에게 보고 의무가 있다는 이유만으로 주민에 대한 위임 근거 부족을 자동 선언하지 않는다.
- 위임 사무·주민 부담 조문은 대상, 사무 성격, 실제 EV 원문과 일치하는 인용, 허용 범위와 담당자의 직접 대조 기록이 남기 전까지 검토 기록을 완료하지 않는다. 법령명·조 번호만 적거나 인용문이 실제 원문과 다르면 미확인으로 남긴다.
- 시행예정 근거를 현재 근거로 연결하면 재확인 대상으로 남긴다. 저장본·사용자 원문·일부 발췌 상태는 숨기지 않는다.
- 담당자가 완료한 상태의 이름은 `담당자 검토 기록`이다. 탐지·사용자 체크·출력물 생성은 자동 적법성 승인으로 바꾸지 않는다.
- 한 번에 한 조문을 고르는 화면과 현재 표현 후보를 제공한다. 입력한 기록은 화면 이동·저장·백업에 재사용한다.
- Parser의 조문 UID는 무작위이므로 저장 주소로 사용하지 않는다. 제정은 지속되는 outline ID, 개정은 조 번호·가지번호를 사용한다. 현재 조문·전체 입력 원문·입안 방식·기관·선택 근거의 텍스트·URL·시행일 등이 달라지면 과거 기록을 남긴 채 재확인을 표시한다.
- HWPX·DOCX 공통 문서 모델용 권한·근거표를 별도 생성한다. 미검토·재확인 상태와 남은 항목도 그대로 출력하므로 파일을 내려받는 행위가 검토 완료를 뜻하지 않는다.

## 검증과 한계

`tests/authority-review.test.ts` 최초 14개, 교차검수 후 17개가 통과했다. 주요 반례는 자치사무의 불필요한 위임 요구, 직원 의무 오탐, 법령명만 있는 근거, 실제 원문과 다른 인용, 미확인 범위, 새로고침 후 무작위 UID, 초안·근거·기관 변경, 연결 근거 삭제, 시행예정 근거, 포괄적 시행규칙 문구다.

현재 자동 검증은 원문 인용의 문자열 일치와 기록의 완결성·최신성을 다룬다. 대상·범위가 실질적으로 맞는지, 위임 경로가 법적으로 충분한지, 적용되는 법령 전체나 판례가 빠졌는지는 자동 확정하지 않는다. 연결 EV의 원문과 담당자 판단을 함께 검토하는 기록 도구이며, 독립 법제 사례 평가와 실제 한컴 프로그램 출력 검증을 대신하지 않는다.

통합 지점: `Project.authorityReview`, `project-transfer.ts`의 `authorityReviewStateSchema`, 작업 점검 화면의 `AuthorityPanel`, 문서 세트의 `buildAuthorityReviewDoc(p, rule)`.

루트의 입안 방식·문서 출력·작업 화면을 별도로 대조하고 `tests/v08-independent.test.ts`에 네 가지 독립 검사를 추가했다. 허구의 문화 지원 조례를 이용했으며 실제 조례의 적법성 평가가 아니다.

| 발견한 위험 | 조치·현재 결과 |
| --- | --- |

| 같은 조문은 그대로지만 다른 정의·적용범위 조문을 바꾸면 권한 검토가 남을 수 있음 | 권한 지문에 활성 본문 전체를 연결. 전부개정 `replacementDraft`, 제정 outline 전체, 일부개정 수락 변경을 기록하므로 관련 맥락 변경도 재확인. |

핵심 원본 PDF 4종과 요청서 HWPX 1종은 manifest의 바이트·SHA-256 모두 일치했다. 추가 출처 안내 TXT에서 발견한 3바이트 BOM 차이도 루트에 보고했고 원본 복원 후 일치 확인을 전달받았다. 원본 다섯 종과 추가 안내문을 구분한다.

현재 입안 방식 자동 제안은 변경 취지의 키워드에 따른 후보일 뿐이다. 변경 비율만으로 전부개정을 확정하지 않고, 방식 전환·근거 기록·출력 다운로드를 법적 승인으로 취급하지 않는다. 종전 부칙 검토·제출 전 법제심사·개별 법령의 현재 효력 확인은 계속 별도 과제로 표시한다.

## 추가 구현: 기관 규정 묶음의 인용 영향 후보

`linked-regulations.ts`와 `LinkedRegulationsPanel`은 현재 작업을 인용하는 다른 규정 원문을 최대 8개, 각 10만 자까지 이 작업에 보관한다. 규정 ID·정확한 제목·종류·시행일·원문 URL·부분 원문 여부·검토 범위 메모를 백업에도 유지한다. 추가·수정·연결 해제는 이 작업 안의 입력 자료를 대상으로 한다. 공유 기관 규정 원본을 수정하는 기능은 아니다.

법규명과 조문 번호를 함께 확인하는 보수적인 문자열 매칭을 사용한다.

- `「정확한 규정명」 제N조`, 가지번호·항, `별표 N`, `별지 제N호서식`만 변경 전 대상과 연결한다. 제목의 공백은 정규화하되 다른 규정명·시행규칙명·약칭은 같은 제목으로 취급하지 않는다.
- 다른 규정 안의 무명 `제5조`를 현재 작업의 제5조로 추정하지 않는다. 인용부호 없이 제목만 적은 표현은 `연결 미확정`으로 분리하고 이동·삭제 대상으로 자동 연결하지 않는다.
- 일부개정의 이동은 같은 엔진 실행의 원래 대상 식별자를 따라 추적한다. 현재 제5조가 과거 다른 조문이었는데 숫자가 같다는 이유로 연결하지 않는다. 삭제되면 업무의 근거·적용범위를 검토할 후보로 남기며 번호만 교체해 완료로 처리하지 않는다.
- 전부개정은 같은 번호·문구도 동일 조문으로 확정하지 않고 원문 재대조 후보로 표시한다. 폐지는 근거·계속 처리할 업무·대체 규정·경과조치 검토로 연결한다.
- 다른 규정의 본문·부칙·별표·서식에 있는 직접 인용의 원문 행과 근접 표제, 주변 문맥, 변경 전후 대상을 함께 보여 준다. 같은 조문 번호가 여러 규정·판본에 있어도 문서 ID를 유지한다.
- 결과는 매번 현재 기준 원문과 현재 파생 초안에서 다시 계산한다. 저장된 승인 상태나 과거 영향 분석을 현재 결과로 재사용하지 않는다. HWPX·DOCX 공통 모델의 별도 영향 후보 검토표도 동일한 계산을 사용한다.
- 원문이 부분적이거나 시행일·주소가 미입력인 상태를 숨기지 않는다. 시행예정 연결 원문은 현행 규정의 영향과 구분해 확인하도록 표시한다. 사용자 전체 원문 대조 기록도 자동 완전성 보증으로 바꾸지 않는다.

원본 길라잡이 PDF 421쪽(본문 413쪽)의 개정 방식, PDF 454–455쪽(본문 446–447쪽)의 별표 개정, PDF 532쪽(본문 524쪽)의 관련 자치법규 확인 흐름을 직접 추출해 읽었다. 구체적인 검색 알고리즘과 8개·10만 자 제한은 해당 매뉴얼의 의무 조항이 아니라 누락·오연결을 드러내기 위한 제품 설계다.

`tests/linked-regulations.test.ts`는 12개 반례를 검증한다. 이름 없는 조문·다른 법규·약칭 제외, 인용부호 없는 이름의 불확실 분리, 이동·삭제·항·별표·서식 변경, 전부개정·폐지, 없는 대상, 여러 문서 식별, 부분 원문과 시행예정 상태, 입력 제한, 백업 왕복을 포함한다.

지원 한계: 기관 전체 규정의 자동 수집이나 간접·다단계 의존관계, 약칭 해소, 연속·범위 인용의 생략된 이름, 인용이 없는 의미상 영향, 표의 행·열·병합 구조는 자동 해석하지 않는다. 화면은 변화 후보 100개, 기타 펼침 목록은 30개씩, 문서 상세는 앞 200개까지 표시하고 초과 개수를 알린다. 보관파일에는 입력 원문 전체가 남는다. 후보 없음은 영향 없음의 결론이 아니며 다른 규정을 자동 수정하거나 정비 완료로 표시하지 않는다.
