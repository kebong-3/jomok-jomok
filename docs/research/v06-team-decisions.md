# v0.6 다섯 역할의 검토·합의 기록

2026-10-26. 총괄을 포함한 다섯 역할이 구현과 독립 검토를 나눴다. 동시에 실행 가능한 수에 맞춰 독립 검수는 구현 후 이어 진행했다.

| 역할 | 담당 | 합의된 결과 |
|---|---|---|
| 총괄·배포 | 전체 작업 흐름, 저장·백업, 시간 한도, 통합, 운영 검증 | 사용자 재확인 없이 이미 승인된 저장소 변경·배포 진행. 실제 배포와 브라우저 결과를 따로 기록 |
| 문서 출력 | 다운로드 차단 원인, 출력 준비 상태, HWPX·DOCX | 일괄 확인 조건을 문서별 준비 상태로 분리. 검토용 파일은 받고 검토 의무는 화면·파일에 표시 |
| 조목이·인지 부담 | 캐릭터와 다음 할 일 카드 | 한 번에 주요 행동 하나를 강조. 파스텔 배경과 진한 본문, 문서 격식 유지 |
| 작업 내 검토 | 현재 조문을 넣은 RAG 검토, 선택 반영, 복구 | 정확히 일치하는 단락 문구만 적용. 전후 문장·근거 확인 후 선택한 수정 일괄 반영 |
| 독립 QA | 구현자와 별도로 실패 사례·회귀 검사 작성 | 원본 보존, 잘못된 인용 거부, 복구·백업, 미확인 다운로드를 공격적으로 확인 |

## 검토 과정에서 고친 구체적인 문제

1. 조문 미확인이나 오래된 이유서가 입법예고문까지 차단했다. 내용 있는 문서는 검토용으로 저장하도록 바꾸고 확인 상태를 자동 완료하지 않는다.
2. 문서 탭 상위 화면이 부분 작성 초안을 먼저 막았다. 조문 체계를 확정한 작업은 일부 미작성 상태에서도 검토용 문서를 받을 수 있게 했다.
3. 개정 파서가 실행마다 조문 UID를 새로 만들기 때문에 검토 적용이 실패했다. 현재 조 번호·가지번호의 안정적인 대응과 원본 주소를 구분했다.
4. 화면 단계가 바뀌어도 이전 검토 상태가 남을 수 있었다. 단계 변경 시 검토 컴포넌트를 새로 구성한다.
5. 문서를 수정한 뒤 이전에 생성한 저장 링크가 남았다. 출력 내용 지문으로 링크를 무효화하고 생성 중 변경도 확인한다.
6. 문자열 치환에서 `$&` 같은 문자를 자바스크립트가 재해석했다. 치환 함수를 사용해 담당자가 보는 문장을 그대로 반영한다.
7. 체크된 문장들이 합쳐져 새 조문 제목을 만들 수 있었다. 단일·일괄 치환 전후의 실제 파서 구조를 검사한다.
8. 점검표의 이유서 검토 지문이 화면과 달라 항상 오래된 것으로 표시될 수 있었다. 같은 지문 함수를 사용한다.

## 상호 검토의 판단 기준

다운로드 편의와 담당자 확인을 양립시키기 위해 상태를 숨기지 않는 검토용 출력을 선택했다. 자동 반영의 편의는 정확한 문자열·대상 단락·현재 스냅샷이 모두 일치하는 범위에서 제공한다. 조목이는 절차를 안내하고 오류를 설명하는 역할이며 법률적 승인이나 최종 결재를 의인화하지 않는다. 근거 원문은 추적 가능하게 남기되 첫 화면에서 피드백보다 먼저 읽도록 강요하지 않는다.
