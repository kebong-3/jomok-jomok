# v0.4 전문 검토 4 — 원문 검색과 RAG 구현

검토·구현일: 2026-10-24. 담당: retrieval_engineer.

> 작업 환경 복구 기록: 검색 서버와 회귀 검사는 대화에 남은 최종 소스로 복원했고 검색 route는 동일 계약으로 재구현했다. 아래 5절은 복구 후 실제 재실행 결과다. 복구 전 관측 전체는 별도 `v04-retrieval-benchmark-pre-recovery.json`에 보존했다. 복구 과정에서 검색 가중치는 변경하지 않았다.

## 1. 결론과 이번 구현 범위

업로드한 공식 PDF 4권 1,997페이지, 공식 HWPX 서식 1개, 사용자 출처 안내문 1개를 앱의 원본 파일과 검색 자료로 연결했다. 최초 배포 준비 시 검색 원문은 2,300개 발췌 단위였고, 환경 복구 후 단락 분할 경계 차이로 현재는 **2,283개**다. 원본 6종의 SHA-256은 복구 전과 동일하며 PDF 1,997페이지도 유지된다. 검색은 서버에서 수행하며, 사용자 브라우저에 전체 원문 색인을 내려주지 않는다.

검색 결과를 AI 호출의 입력으로 넣는 RAG 구조다. **BM25 계열 단어 점수와 한국어 문자 매칭을 결합한 로컬 검색**이며, 임베딩 모델·벡터 데이터베이스를 사용했다고 표현하지 않는다. 원문 검색에는 별도 API 키, 유료 데이터베이스 또는 외부 검색 서버가 필요하지 않다. 설명·문안 작성에는 기존 앱의 모델 어댑터를 사용한다.

이 선택은 고정된 참고자료 6종을 여러 기관으로 이전할 때의 비용·설정 부담을 줄이고, 같은 자료와 검색어에 대해 재현 가능한 검색 결과를 제공한다. 임의 PDF를 계속 업로드하는 대형 지식관리 서비스 전체를 구현한 것은 아니다.

## 2. 서로 다른 사실 확인을 섞지 않는다

| 구분 | 이번 검색이 확인하는 것 | 확인하지 않는 것 |
|---|---|---|
| 원본 SHA-256 | 업로드한 원본과 앱의 내려받기 파일 바이트 일치 | 법제처가 이 해시를 공식 공표했다는 의미 |
| 발췌문 SHA-256 | 수집된 텍스트와 AI에 전달한 발췌문 일치 | 그림·표의 의미를 완전히 복원했다는 의미 |
| PDF 페이지 | 첨부 원본 안에서의 실제 물리 페이지 | 법령의 시행일·현행성 |
| 인쇄 쪽수 | 원문에서 확인된 본문·부록의 쪽수 | 표지·판권에 추측으로 부여한 쪽수 |
| 원문 인용 일치 | AI가 인용한 문구가 전달된 원문에 존재 | 그 문구가 답변의 법적 결론을 충분히 뒷받침한다는 의미 |
| 검색 성공 | 질문과 관련된 참고 기준의 발견 | 법률상 위임·권한·적법성 확인 완료 |

KB 자료는 매뉴얼·서식 참고 근거이며 EV 법령 근거를 대신하지 않는다. 알법의 정비 사례에는 법적 요건과 숫자가 함께 변경된 사례도 있어, 단순한 정비 전후 학습쌍으로 만들어 자동 치환하지 않는다.

## 3. 실제 토론과 설계 변경

### 역할 1(자치법규 실무)과의 토론

검색 상위 6개를 모두 독립 문서처럼 전달하면 좁은 체크리스트 문장만 남고 예외·주의가 사라질 수 있다는 문제를 제기했다. 역할 1은 **핵심 결과 4개와 인접 예외 1~2개 보강**에 동의하면서, “다만” 같은 단어만으로 무관한 판례·구법 사례를 붙이면 안 된다고 지적했다.

이에 자동 AI 입력에서는 같은 원본·같은 페이지의 후속 발췌 또는 인접 페이지 중 특정 절 제목이나 여러 실질 주제가 겹치는 본문만 보강한다. 공통 머리말 “제2편 법령 입안·심사의 세부 기준”만 같은 경우에는 같은 절로 인정하지 않도록 수정했다. 이 보강은 모든 예외를 빠짐없이 찾았다는 보장이 아니므로 원본 페이지 열기를 함께 제공한다.

### 역할 2·3의 자료 분석에 대한 검토

법률·조례·자치규칙·행정규칙의 적용대상 혼동과, 알기 쉬운 용어 정비에서 법적 의미를 잃는 문제가 검색 이후 생성 단계까지 이어진다는 지적을 반영했다. 규정 종류는 검색 자료의 우선순위를 바꾸지만 다른 일반 기준을 완전히 숨기지 않는다. 알기 쉬운 문장 검토는 알법 기준을 우선하며, 의견제시 요청 준비는 공식 서식을 우선한다.

정비 제외·시행 전 개정·전부개정의 종전 부칙 등 예외를 확인할 수 있도록 본문을 목차보다 우선한다. 매뉴얼이 특정 기준일의 법령을 인용한 경우도 현재 법령으로 바꾸어 표시하지 않는다.

### 역할 5(독립 품질 검토)와의 토론

역할 5는 검색 적중률, 인용 문구 일치, 법리적 답변 타당성이 서로 다르다는 점을 지적했다. 이 의견을 수용해 검색 벤치마크를 AI 답변 정확도나 심사점수로 사용하지 않는다. 또한 목차·짧은 체크리스트의 높은 점수가 적용 제외 대상을 가리지 않도록 인접 본문 보강과 문서 유형 가중치를 별도로 둔다.

독립 검토자가 검색 순위를 보기 전에 작성한 별도 8질의를 실제 실행했다. 첫 실행에서 가지조문 범위 인용과 입법 재위임의 두 문제를 발견했다. 이를 고치는 데 8질의를 사용했으므로 보정 후 결과는 이제 개발 반례 기록이며 독립 시험 정확도로 제시하지 않는다.

가지조문 질문은 예시 조 번호가 다른 페이지와 우연히 일치해 직접 설명이 있는 자치법규 PDF 440쪽을 놓쳤다. 예시 조 번호는 주제어 점수에서 빼고 “제N조의N”을 가지조문 개념으로 인식하도록 바꿨다. 보정 후 해당 쪽이 1위로 검색된다. 입법 재위임 질문은 구청장의 사무 재위임을 다루는 PDF 319쪽이 1위였다. 법률→조례→고시·규칙의 입법 형식 질문과 사무·업무 수행의 위임 질문을 구별해, 입법 형식 개념을 확장하고 해당 의도에서만 사무 재위임 사례의 순위를 낮췄다. 이후 자치법규 PDF 24쪽이 1위, 23쪽이 4위로 검색되고 사무 재위임 쪽은 상위 6개에서 빠진다. 정답 페이지 번호를 검색 구현에 넣지는 않았다.

주 담당자의 추가 검증에서는 “오늘 저녁 피자 맛집 추천”이 생활 예문의 우연한 단어 겹침 때문에 검색되는 문제가 드러났다. 긴 질문의 단일 우연 단어 일치를 제외하는 커버리지 조건을 넣고, “시행하지 않은→미시행”처럼 명시적인 법률 동의개념은 보존했다. 식당·음식 단어 블랙리스트 없이 이 질문은 결과 없음으로 반환되며, 도움 API가 모델을 호출하지 않는 검사도 통과한다.

## 4. 검색 구현

### 최초 로딩

1. `data/knowledge/corpus.json.gz`의 전체 SHA-256을 manifest와 대조한다.
2. 압축 해제 크기를 20MB 이내로 제한한다.
3. 자료 버전, 발췌 개수, 문서 ID, 중복 발췌 ID, 발췌문 지문을 확인한다.
4. 단어·주제어·한국어 2/3음절 문자열의 빈도와 문서 빈도를 구성한다.
5. 같은 서버 인스턴스에서는 메모리에 한 번만 캐시한다.

파일이 없거나 지문이 다르면 검색 API는 503 오류를 반환한다. 원본 자료를 찾았다고 꾸미거나 빈 배열을 성공 상태로 위장하지 않는다. 자동 생성 단계에서는 검색 실패를 기록하고 현재 AI 흐름에 전달할 수 있다.

### 검색 점수

- 한국어 조사·어미를 제한적으로 정리한 단어 BM25 점수를 사용한다.
- 조문 체계·부칙·위임 등 실제 입안 주제어를 붙여 쓴 문장에서도 찾는다.
- “전문개정/전부개정”, “가지조문/가지번호” 등 업무 용어 관계를 낮은 가중치로 확장한다.
- 한국어 문자 매칭은 띄어쓰기·조사 차이를 보완한다. 문자 조각만 같고 직접적인 의미어가 없는 결과는 반환하지 않는다.
- 본문 소제목을 가중하고, 구분·차이 질문은 해당 개념을 함께 비교하는 소제목을 우선한다.
- 본문보다 목차·앞부분 가중치를 낮춘다.
- 같은 원본 페이지의 겹치는 발췌를 일반 검색 결과에서 중복 근거처럼 나열하지 않는다.
- 긴 질문에서 한 단어만 우연히 겹치는 결과는 제외한다. 법률 주제어·명시적 동의개념의 일치는 별도로 보존한다.
- 예시 조 번호는 숫자 자체보다 가지조문 등 그 구조를 검색한다. 입법 형식의 재위임과 사무 재위임은 질문 문맥을 구별해 순위를 정한다.

검색 키워드 목록은 토큰화 보조용이며, 특정 질문을 정답 페이지로 보내는 규칙이나 예상 답변은 들어 있지 않다. 현재 여섯 자료 외의 문서·임의 경로를 조회할 수 없다.

### 입력 계약

`GET /api/knowledge/search`

| 매개변수 | 의미 |
|---|---|
| `q` | 2~2,000자 검색어 |
| `documentIds` | 등록된 자료 ID를 쉼표로 연결; 생략하면 전체 |
| `kind` | 법령·조례·규칙·훈령·예규·고시·지침·내규의 종류 값 |
| `mode` | `explain`, `review`, `plain_language`, `opinion_request` |
| `limit` | 1~12개, 기본 6개 |

정상 응답은 질문, 검색 결과, 후보 수, 자료 버전, 방법, 소요시간을 포함한다. 검색 결과에는 자료명·판본·수록 기준일·PDF 페이지·확인된 인쇄 쪽수·공식 출처·앱 원본 경로·실제 발췌문·지문이 들어 있다. 없는 자료 ID, 잘못된 종류·모드·결과 수는 400 오류다.

자동 제·개정 AI 단계에서는 `retrieveForRole`을 사용한다. 질문·개정 의도·목적을 먼저 검색하고, 역할에 필요한 일반 기준은 제한적으로 보강한다. 각 역할의 발췌문과 출처 정보를 포함한 전달량은 약 7,000자 한도다. 검색 결과가 많다는 이유로 사용자 규정 전체를 잘라 버리거나 다른 규정의 조문을 적용하지 않는다.

## 5. 검증과 관측 수치 — 환경 복구 후 실제 재실행

복구 후 검색 기능 검사 10개와 60질의 벤치 측정 1개, 총 11개가 통과했다. 원본 6종 파일 지문, 실제 적용례 본문 검색, 가지조문 삭제·인용 범위, 입법·사무 재위임 구별, 알법 부록 100쪽 대응, HWPX의 쪽수 미조작, 무관 질문의 검색 결과 없음, 입력 제한, AI 전달 원문·길이·지문, 검색 API 오류 상태를 확인했다.

복구 전에는 검색 10개·도움 API 9개·별도 검토 질문 8개, 총 27개가 통과했다. 이 과거 통합 실행을 복구 후의 현재 전체 앱 검증으로 간주하지 않는다. 별도 검토 질문의 테스트 통과는 검색 형식과 일부 방어 조건의 통과이며 8개 법리 답변의 정확도 판정도 아니다.

별도 옵션으로 세 법제 전문가가 작성한 개발용 질의 60개를 다시 실행했다. 보존된 실측 JSON에서 원래 질문과 예상 페이지를 그대로 읽으며 질문·예상 범위를 바꾸지 않았다. 이 질의 집합은 최초 토큰화·가중치 개선 과정에서 사용되었으므로 독립 시험 세트가 아니다.

| 개발 질의 분류 | 수 | 해당 자료 지정 검색 hit@6 | 전체 자료 + 종류/모드 검색 hit@6 |
|---|---:|---:|---:|
| 자치법규 입안 | 20 | 20 | 20 |
| 법령 입안 | 12 | 12 | 11 |
| 행정규칙 입안 | 8 | 8 | 7 |
| 알기 쉬운 정비 | 16 | 16 | 16 |
| 의견제시 요청서 | 4 | 4 | 4 |
| 합계 | 60 | 60 | 58 |

PDF 56질의는 전문가가 정한 **물리 페이지 범위가 상위 6개에 있는지** 측정했다. HWPX 4질의는 해당 서식이 검색되는지 확인했으며 서식 항목별 정답률로 계산하지 않는다. 전체 검색에서 놓친 두 질의는 다음과 같다.

1. “기존 일부개정법률 부칙을 개정할 때 공포번호도 적어야 하나요?” — 예상 법령 PDF 833~835쪽. 전체 검색에서는 유사 조례 사례와 인접 개정 사례가 먼저 나온다.
2. “행정규칙에서 지방자치단체 조례로 정할 사항을 직접 정하거나 위임 범위를 좁힐 수 있나요?” — 예상 행정규칙 PDF 98~99·106~107·149쪽. 전체 검색에서는 다른 위임 범위·자치입법 설명이 앞선다.

둘 다 해당 자료로 범위를 좁히면 상위 6개에서 예상 쪽을 찾는다. 실패와 관측 순위를 결과 파일에 그대로 남겼다. 최초 개발 중간 결과 59/60에서 최종 58/60으로 바뀐 사실도 숨기지 않는다. 복구 후 새 corpus에서도 동일한 두 실패와 58/60이 관측됐다. 입법·사무 위임 혼동과 무관 질문 오탐을 줄이는 데 우선순위를 두었으며, 개발 벤치 점수만 높이는 추가 가중치 조정은 하지 않았다.

복구 후 관측에서 이미 색인된 전체 자료 검색 60회의 중앙값은 **18ms**, 최대는 **38ms**였다. 해당 실행의 최초 검색은 약 **1.86초**가 걸렸다. 복구 전의 중앙값 21ms·최대 49ms 기록은 과거 JSON에 별도로 보존했다. 이는 개발 환경에서의 관측이고 Vercel의 콜드 스타트·브라우저 왕복·AI 생성 지연을 포함한 운영 응답시간이 아니다.

복구 전 별도 8질의 중 기존 위원 임기는 자치법규 PDF 385·384·383쪽, 반수와 과반수는 알법 PDF 157쪽, 공단 재검토기한은 행정규칙 PDF 144쪽 체크리스트와 41·40·42쪽 적용대상·예외가 함께 검색됐다. 자료가 없는 기관 규칙의 위법 여부나 2027년 최신 공포번호를 묻는 질문에는 일반 매뉴얼이 검색될 수 있으므로, 결과 존재 자체를 개별 규정의 적법성이나 현행성 답변으로 삼을 수 없다.

## 6. 적용 한계와 후속 선택

개발 질의의 검색 적중 건수를 법률 정확도, 직원 업무효율 또는 대회 심사점수로 표현하면 안 된다. 임베딩·재순위화 모델이 없는 만큼 같은 뜻이지만 단어가 완전히 다른 질문에는 검색 한계가 있다. 검색되지 않으면 쟁점 용어·자료 필터를 안내하고, 없는 근거를 만들어 주지 않는 편이 낫다.

전체 PDF 페이지를 처리했지만 이미지 내부 글자 OCR, 표의 셀 결합 관계, 도표의 의미를 완벽히 복원하지 않는다. 발췌문은 페이지 원본과 대조할 수 있게 해야 한다. 첨부 자료의 판본 시점 이후 법령 개정 여부는 별도 공식 API와 원문 확인이 필요하다.

기관이 문서를 계속 추가하는 단계에서는 임베딩과 벡터 저장소, 자료별 접근권한, 갱신 작업을 확장할 수 있다. 이번 고정 자료 검색이 정상 동작하는 데 그 서비스들의 키를 요구하지 않는다. 모델 생성 부분은 현재 제공자 어댑터를 유지하여 특정 LLM에 종속되지 않게 한다.
