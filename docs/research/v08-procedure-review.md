# v0.8 행정 절차·의견제시 문서 반영 검토

검토일: 2026-10-27
담당 역할: 다섯 역할 중 행정 절차·의견제시 문서

## 확인한 원문과 범위

`public/references/opinion-request.hwpx`의 `Contents/section*.xml`을 직접 읽어 요청요건 체크표와 본문 항목을 확인했다. 원본에 들어 있는 체크 기호, 00월 00일, 국정과제 번호 46과 그 내용은 예시다. 이를 실제 요청기관·단계·날짜·정책 관계의 사실값으로 사용하지 않았다.

원본 사전 확인 구조는 요청권한자, 자치법규 형식, 요청·관련 지자체 소관 여부와 업무관련성, 입법단계, 질의 특정, 일반적 해석 여부, 국정과제 및 지방시대 시행계획 관련성이다. 본문은 질의배경, 질의요지, 대상 조문·관련 법령, 대립되는 견해, 요청·관계기관 의견, 참고자료의 여섯 부분이다. 원본이 대립되는 견해가 없으면 생략할 수 있다고 안내하므로 갑설·을설을 AI가 자동 창작하도록 만들지 않았다.

`local-ordinance-2026.pdf` PDF 539–541쪽(인쇄 531–533쪽)을 직접 추출해 재예고 검토 사례와 제출 의견 처리·통지 설명을 확인했다. 신규 의무·제재뿐 아니라 혜택의 축소, 일부 수혜 확대가 제3자 이익·공익에 미치는 영향, 입법 취지 변화, 시행일·유효기간·적용례·경과조치의 불리한 변경을 검토 후보에 포함했다. 문자 변경이 없더라도 장기간 지연이나 입법환경 변화가 있을 수 있으므로 ‘변경 없음=재예고 불필요’로 처리하지 않는다.

`administrative-rules-2025.pdf` PDF 18·22·24쪽(인쇄 14·18·20쪽)을 직접 확인했다. 해당 설명은 중앙행정기관의 등재·행정예고·관계기관 의견수렴·규제 검토 절차를 다룬다. 그 절차와 기간을 지방자치단체·공공기관 내부규정에 일괄 적용하지 않도록 화면과 출력물에서 적용 절차·기관 기준을 직접 기록한다.

이 검토는 제공 자료의 해당 판본과 쪽을 제품 입력·출력 구조에 연결한 것이다. 1,997쪽 전체 정독이나 개별 사안의 현재 법령 효력을 확정한 것으로 주장하지 않는다.

## 반영한 업무 방식

### 의견제시 요청서 작성자료

- 요청 권한·형식·소관·단계·구체적 쟁점·정책 관련성을 각각 저장한다. 미확인, 해당 없음, 실제로 확인한 내용을 구분한다.
- 현재 작업에서 기관 설정의 이름, 대상 제목·형식, 현재 초안, 보존한 근거 원문을 **명시적 가져오기 버튼**으로 빈 칸에만 채운다. 기존 입력을 덮어쓰지 않는다.
- 실제 요청 명의, 입법단계, 날짜, 견해, 기관 의견과 체크 결과는 가져오기로 결정하지 않는다. 200,000자 입력 한도로 발췌되면 그 사실을 본문에 표시하고 완료 확인 대상으로 남긴다.
- 소속기관·산하기관·의원 개인 명의, 업무관련성 미작성, 전체 적법성 질의, 구체적 사실인정·처분 판단, 의결·공포 후 상위법 위반 여부 등 원본 서식의 반려 가능 사유를 드러낸다. 일반적 해석 요청과 의결 후 적법성 질의는 구분한다.
- 대립 견해가 없다는 명시적 기록을 허용한다. 견해나 관계기관 의견이 있다고 선택하면 실제 논거·회신 출처를 요구한다.
- 작성내용 확인은 작업 본문·상위법 근거·기관·입력 내용 지문과 결합한다. 변경되면 이전 확인은 재확인 상태가 된다. 지문은 UI의 변경 감지 수단이며 법적 승인이나 암호학적 서명이 아니다.
- 출력은 **공식 원본의 항목에 맞춰 재구성한 작성자료**다. 원본의 체크칸·배치에 직접 기입한 완성 원본이 아니다. 이 차이를 화면, 파일 본문과 서식 출처에 명시하며 공식 원본 HWPX 다운로드를 유지한다.

### 제출의견 처리·재예고 검토

- 입법예고·행정예고·내부 의견수렴·해당 없음을 구분하고 적용 근거를 저장한다.
- 실제 접수 의견의 유무도 별도로 확인한다. 접수 의견 없음은 확인한 접수 내역을 기록하며, 의견 목록과 모순되면 확인사항으로 남긴다.
- 제출 의견별 요지, 처리 결과, 이유, 실제 반영·관련 조문, 결과·이유 통지 상태와 실제 통지 기록을 저장한다. 기록만으로 본문을 바꾸거나 통지를 보내지 않는다.
- 반영 조문은 현재 규정의 실제 조·가지번호·명시 항과 대조한다. 처리 내용·본문·절차 기준이 바뀌면 이전 검토가 재확인 상태가 된다.
- 통지 준비 중이라는 기록은 보관할 수 있으나 실제 통지가 남았다는 일을 계속 표시한다.
- 비교 기준은 담당자가 명시적으로 보관한 본문이다. 기준을 교체해도 기존 원문을 이력에 보존하며 20개·총 2MB 범위를 넘으면 기존 내용을 지우지 않고 새 보관을 중단한다.
- 폐지 작업의 비교 본문은 기존 규정 전문이 아니라 실제 폐지문과 새 부칙이다.
- 변경 문맥에서 권리·의무·제재, 지원·혜택·자격, 제3자 영향, 첫 조문·목적, 부칙의 변화 후보를 찾는다. 숫자만 변해서 ‘과태료’ 등의 단어가 그대로인 경우도 주변 문맥으로 찾는다. 모든 후보는 검토 질문이며 법적 결론을 자동 선택하지 않는다.
- 재예고 필요·불필요·추가 법무 검토라는 담당자의 판단과 이유를 저장한다. 필요 기록은 실제 재예고 완료를 뜻하지 않는다.

## 검증과 남은 범위

새 절차 검증은 요청요건의 구체적 분기, 확인 전 상태, 본문·기관·근거 변경 시 재확인, 실제 조문 연결, 통지 대기, 재예고 후보와 담당자 판단의 구분, 악의적 지시가 데이터로만 출력되는지, 공개 주소 제한, 예고안 이력·지문, 백업 왕복 보존을 다룬다. 요청서의 사전 요건과 본문 1–6항의 실제 입력이 HWPX·DOCX 양쪽 본문에 포함되는지 검사한다. HWPX는 ZIP·XML·참조·표 구조 검사를 통과하고 DOCX XML도 유효한지 확인한다.

기관의 한컴 한글에서 원본 서식과 작성자료를 실제로 열고 배치 대조·수정·저장·인쇄하는 검증은 별도로 남는다. 일반 문서 패키지 구조 검사를 공식 서식의 완전한 배치 일치나 접수 가능성 검증으로 대신하지 않는다. 실제 법적 요청권한과 관할, 개별 법령의 현행성·적용 범위, 재예고 의무·예외 및 기관의 결재·제출·공고·통지는 담당자와 법무 부서가 확정한다.
