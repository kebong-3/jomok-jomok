# v0.8 자료 재검토와 다섯 역할의 구현 결정

검토일 2026-10-27. 기준 소스 v0.7.0에서 시작했다. 이전 대화의 v0.7 후속 기획과 사용자가 제공한 핵심 원본 5종을 대조하고 실제 입력·판단 기록·산출물로 연결했다. PDF 1,997쪽 전부를 새로 정독했다는 주장은 하지 않는다. 각 역할 보고서에 집중 검토한 물리 페이지와 책자 쪽을 기록했다.

## 역할과 상호 검토

| 역할 | 맡은 구현 | 상호 검토에서 확인한 점 |
| --- | --- | --- |
| 1 입법 권한과 근거 | 조문별 대상·사무 성격·주민 부담·EV 근거와 위임 범위, 여러 기관 규정의 인용 영향 후보 | 일부개정·전부개정·폐지 전환에서 본문 혼용과 실제 없는 대비표 별첨 문구를 독립 재현. 참고 조례·매뉴얼을 위임 근거로 연결하는 경로 차단 |
| 2 부칙과 적용 관계 | 기존 신청·계약·임기·제재·서식 준비, 적용례·특례·경과조치, 종전 부칙 검토, 본칙 마지막 일몰 조문 | 미확인 결론을 문장으로 채우지 않음. 확인 뒤 본문·시행일이 달라지면 제외하고 재확인. 전부개정·폐지 간 전환도 종전 부칙 판단에 반영 |
| 3 행정 절차와 문서 | 의견제시 요청 항목과 작성자료, 제출의견 처리·통지·재예고 검토, 예고 기준안 이력 | 원본의 예시 체크·날짜·국정과제를 사실로 재사용하지 않음. 접수 의견 없음도 직접 확인하고 기존 예고안을 이력에 보존 |
| 4 자료 검색과 검증 | 복합 쟁점 분해·배분 검색, 검토 입력 범위, 전부개정의 정확한 문장 반영·되돌리기 | 출처 인용 일치와 법적 적용 적합성을 구분. 선택하지 않은 본문·별표·서식·공백·CRLF를 보존하고 백업 복원 후에도 되돌리기 검증 |
| 5 통합과 품질 검수 | 전부개정·폐지 작업, 공통 문서·다운로드·저장·다음 행동 안내, 회귀검사·빌드·배포 확인 | 새 전체 본문이 없으면 기존 원문을 완성한 전부개정안처럼 출력하지 않음. 방식별 이유서·예고문·붙임과 실제 문서 세트를 일치시킴 |

동시에 실행 가능한 에이전트 수에 맞춰 작업을 순차 배치했다. 다섯 역할 모두 실제 코드를 작성하거나 독립 시험으로 상호 검토했으며, 단순한 가상 역할 토론을 구현 완료로 계산하지 않았다.

## 합의한 구현 원칙

모든 일반 자치사무 조례에 개별 법률 위임을 요구하지 않는다. 반대로 법령명이나 유사 조례를 입력했다는 이유로 위임 범위를 확인한 것으로 표시하지 않는다. 권한표의 확인은 담당자 기록이며 적법성 승인이 아니다.

검토 상태는 입력 당시 본문·근거·기관·시행일에 연결한다. 기존 기록을 없애는 대신 현재 초안과 다르면 재확인으로 표시한다. 부칙은 확인한 문장만 출력하며 미확인과 제외 사실도 검토표에 남긴다.

공식 요청서의 모든 입력 항목을 연결하되, 출력은 원본 배치에 직접 채운 문서가 아니라 재구성한 작성자료임을 명시한다. 원본 HWPX 다운로드는 유지한다. 파일을 받는 행동을 결재·예고·접수·법적 승인 완료로 처리하지 않는다.

RAG는 질문과 입력 본문 전체에서 쟁점 단서를 탐지한다. 기존 최대 6개·5,500자 예산을 유지하면서 쟁점을 순환 선택한다. 근거 미발견·예산 제외·입력 조문을 기록하며, 이 기록은 모든 쟁점을 빠짐없이 법적으로 검토했다는 증명이 아니다.

다른 규정의 인용은 규정명과 조·항·별표·서식의 실제 표기를 바탕으로 연결한다. 무명 ‘제5조’·다른 규정·약칭을 임의 연결하지 않는다. 삭제·전부개정·폐지는 번호만 바꾸어 해결했다고 표시하지 않는다.

## 이번에 주장하지 않는 내용

- 독립 법제 전문가가 확인한 적법성 정확도와 공공 AI 챌린지의 새 점수
- 실제 주무관의 업무시간 절감률이나 누락 감소율
- 한컴 한글의 실제 열기·편집·재저장·인쇄 검증
- 별표의 병합 셀·도형·그림을 보존하는 구조 편집
- 공포 후 시행 전 규정의 복잡한 추가 개정을 자동으로 확정하는 기능
- 브라우저를 닫은 동안 서버에서 계속 실행되는 작업 큐
