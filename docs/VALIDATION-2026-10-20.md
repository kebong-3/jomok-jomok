## 1. 현재 판단

운영 주소가 환경변수 없는 Vercel 프로젝트에 연결돼 있던 문제를 바로잡고, 실제 AI 호출과 법제처 현행 법령 조회를 복구했다. 가상 예시를 재생하는 방식 외에, 새로 입력한 개정 요청을 Gemma로 처리하여 조문 수정안·개정문·신구조문대비표·이유서와 다운로드 문서까지 확인했다.

현재 확인된 개정 시나리오에서는 기한 변경, 항 신설에 따른 번호 이동, 다른 조문의 인용 정정이 문서에 일관되게 반영됐다. 다만 Groq의 인증 실패가 남아 있어 두 모델에서 주요 기능이 정상 작동했다고 볼 수 없다. 제정에서는 요청한 3개 조문의 체계·초안, 확정 본문 기반 이유서의 실제 AI 생성, 확인 전 다운로드 차단과 확인 후 문서 다운로드까지 성공했다. 제정 ZIP의 10개 문서 내용·구조 검사와 대표 2개 문서의 시각 검사도 통과했다. 한컴 한글에서의 HWPX 실제 열람은 아직 미검증이다.

첨부 공고의 세션2 배점을 적용한 자체 평가는 최초 상태 **49점**, 현재 **76점**이다. 이는 아래 검증 범위에 한정한 판단이며, 공식 심사 점수나 예선 통과 확률이 아니다.

## 3. AI가 실행되지 않던 원인과 조치

### 3.1 운영 주소와 환경변수의 연결 불일치

같은 GitHub 저장소가 Vercel의 두 프로젝트에 연결돼 있었다. 사용자가 입력한 `GROQ_API_KEY`, `GOOGLE_API_KEY`, `LAW_OC`는 `kevin-jeong/jomokjomok-law`의 Production에 있었지만, 사용자가 접속한 `jomokjomok.vercel.app`은 환경변수가 없는 프로젝트를 서비스하고 있었다.

운영 도메인을 환경변수가 있는 프로젝트의 Production으로 연결했다. 사용자가 키를 입력하지 않았던 것으로 결론 내릴 문제가 아니었다. 이후에도 환경변수는 실제 운영 주소가 연결된 프로젝트의 적용 환경과 새 배포 여부를 함께 확인해야 한다. 값은 이 보고서·소스·검증 기록에 포함하지 않는다.

### 3.2 실제 모델 인증 상태

| 모델·시험 | 결과 | 해석 |
|---|---|---|
| Gemma 4 31B, 짧은 실제 응답 시험 | 약 1.2초에 실제 응답 확인 | 등록 여부뿐 아니라 제공사 호출 성공을 확인함. 개정안 생성 시간과는 다른 측정임 |
| Gemma, 새 개정 입력의 변경안 생성 | 약 29.3초에 성공 | 준비된 예시 응답이 아닌 실제 요청 처리 확인. 단일 측정이므로 평균 응답시간으로 제시하지 않음 |
| Gemma, 개정 이유서 | 실제 AI 응답 및 담당자 확인 단계 확인 | 사용자 검토를 거친 뒤 내려받는 흐름 확인 |
| Gemma, 제정 이유서 | 확정 본문을 사용한 실제 AI 생성 성공 | 문장 수동 수정 없이 확인을 거쳐 제정 ZIP 다운로드 |
| GPT-OSS 120B, Groq | HTTP 401 인증 거절 지속 | 현재 등록된 인증정보로는 정상 사용이 확인되지 않음. 유효한 인증정보 확인·교체 후 재시험 필요 |
| 두 모델 비교 | 미완료 | Gemma의 성공이나 모델 선택 목록만으로 두 모델의 주요 기능 정상 구동을 입증하지 않음 |

기존에는 클라이언트의 짧은 시간 제한과 제공사별 실패·재시도가 겹쳐, 응답 가능한 모델의 실행 시간이 부족해지는 문제가 있었다. 요청 전체의 시간 예산을 정리하고, 한 요청에서 인증 실패가 확인된 제공사를 반복 호출하지 않도록 수정했다. AI 실패를 준비된 예시의 성공으로 오인하지 않도록 실제 모델·예시 사용·실패 원인을 구분한다.

공개 서버의 Gemma 4는 동기 요청 시간 안에 초안을 받을 수 있도록 `thinkingLevel: minimal`을 기본으로 사용한다. 모델은 `gemma-4-31b-it`이며, `GOOGLE_THINKING_LEVEL=high`는 별도 선택이다. 이 설정 변경이 모든 난도의 입안 품질을 유지한다는 비교 실험은 수행하지 않았다. 최종 문안은 사람이 검토하는 구조를 유지한다.

## 4. 유지한 설계와 주요 수정

변경명세 `ChangeSpec`를 단일 원천으로 유지했다. 사용자가 수락한 변경을 기준으로 규칙 엔진이 개정문·대비표·번호 이동·인용 정정·부칙·형식 점검을 계산한다. AI 제안과 담당자 확인을 구분하며, 미검토·거절된 변경이나 확인하지 않은 이유서가 완성된 산출물처럼 내려받아지지 않도록 흐름을 보완했다.

| 영역 | 이번 수정의 목적과 결과 |
|---|---|
| 실제 AI와 예시 구분 | 원본 그대로의 예시 입력에서만 준비된 응답을 재사용. 예시의 원문·의도·기관이 바뀌면 그대로 답을 재생하지 않음 |
| 모델 비교 | 지정한 비교 모델의 실패를 다른 모델·예시의 성공으로 대체하지 않음 |
| 번호·인용·문서 | 항 신설·이동과 인용 정정, 수락·거절 결과 및 문서 간 일치를 보완하고 회귀검증 추가 |
| 이유서 | 개정 요청문을 그대로 이유서로 가장하지 않고, 실제 문안 생성과 사용자 확인을 구분 |
| 규정 종류별 안내 | 지침에 대한 예고문 종류·조사와 조건부 적용 안내를 수정 |
| 원문 보존 | 사용자가 다시 실행할 때 기존 작업을 보존하고 새 작업으로 진행하도록 구성 |
| 법령 근거 | 시행일 기준 현행 조회, 미래 시행본 제외, 요청한 법령명과 본문 제목·조문 구조 확인 |
| 실패 표시 | 키 없음·인증 실패·차단·비정상 응답·읽을 수 없는 조문을 구분. 저장본과 실제 조회를 구분 |
| 배포·이관 | Node 22 환경 고정, CI에서 테스트·빌드·타입검사, 환경변수 예시와 README 보완 |

외부 법령 개정 전후 자동 영향 분석, 전국 유사 조례 비교 등은 README에서도 완성 기능으로 표현하지 않는다. 모델 목록에 표시되는 모든 제공사·모델을 실호출 검증한 것은 아니다.

## 6. 새 입력을 사용한 개정 전체 흐름

내장 예시가 아닌 합성 규정인 검증용 신청서 처리지침을 입력했다. 검증 목적은 서로 연결된 변경이 같은 결과물을 만드는지 확인하는 것이다.

| 요청·검증 기준 | 확인 결과 |
|---|---|
| 기존 제출 기한 5일을 7일로 변경 | 조문 수정안, 개정문, 대비표, 개정 후 전문에 반영 |
| 전자우편 제출에 관한 제2항 신설 | 새 제2항이 반영됨 |
| 기존 제2항을 제3항으로 이동 | 기존 내용이 제3항에 보존됨 |
| 제3조에서 인용하던 제2항을 제3항으로 정정 | 개정문·대비표·개정 후 전문에 일치하게 반영 |
| 변경안 수락·검토 | 실제 화면에서 진행 |
| 개정 이유서 | 실제 AI로 작성한 문안을 확인하고 사용자 확인 단계를 진행 |
| 문서 내려받기 | 실제 브라우저에서 ZIP을 받아 독립 검사 수행 |

이 결과는 위 합성 시나리오에 대한 확인이다. 여러 장·절, 복잡한 가지번호, 다수 별표, 경과조치가 포함된 실제 기관 규정 전반의 정합성을 입증하지는 않는다.

## 7. 내려받은 개정 문서 검사

실제 다운로드 ZIP에 포함된 **DOCX 6개와 HWPX 6개**를 검사했다. 문서 종류는 개정안, 신구조문대비표, 개정이유 및 주요내용, 행정예고문 검토용, 입안점검표, 개정 후 전문 참고본이다.

| 검사 | 결과 |
|---|---|
| ZIP·문서 컨테이너 | CRC와 XML 구조 검사 통과 |
| DOCX와 HWPX의 본문 일치 | 6개 문서 쌍 모두 공백을 정규화한 텍스트 일치 |
| 핵심 변경 내용 | 5일→7일, 제2항 신설, 기존 제2항의 제3항 이동, 제3조 인용 정정 확인 |
| 이유서 내용 | 요청 변경과 자동 인용 정정을 설명하는 내용 확인 |
| DOCX 화면 검사 | 최초 다운로드의 6개 DOCX를 총 7페이지로 렌더링하고 전 페이지 검사. 검사 환경에서 한글 누락·글자 겹침·표 넘침 미관측. 수정 후 ZIP은 내용·구조를 재검사했으며 새로 렌더링하지 않음 |
| HWPX 구조 | mimetype, 패키지 구성, 매니페스트 대상, 서식 참조 ID 검사 통과 |

DOCX 화면 검사는 LibreOffice와 Noto Serif CJK KR 대체 글꼴을 사용했다. Windows Microsoft Word 또는 한컴 한글의 실제 줄바꿈·페이지 배치를 모두 검증한 것으로 해석하지 않는다.

[저장소의 제정 문서 검증 기록](validation/enactment-export.json). 최초 구조·시각 검사 ZIP은 81,062바이트이며 SHA-256은 `4a1ba8c603a2876d1ae1beb6f36c80582cdeb885d19d2e43c7a75f531d258b11`이다. 최종 내용 재대조 ZIP은 81,152바이트이며 SHA-256은 `6aa839a45638e3c4063a159db0df2112974c91d1ff0786e97d1e7dce84ecf2b9`이다. 저장소에는 원본 ZIP·렌더 이미지·별도 원본 QA 파일을 포함하지 않는다. 연결된 JSON은 남아 있는 초기 `enact-export-final-qa.json`에서 작업환경 정보를 제거한 검사 결과와, 이전 세션의 최종 내용 대조 관찰을 복원한 요약을 구분해 담는다.
