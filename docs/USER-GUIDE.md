## 조목이와 시작하기

홈에서 큰 조목이 옆의 **새 규정 만들기** 또는 **기존 규정 고치기**를 선택하세요. 내 자료 없이 흐름을 먼저 보고 싶다면 바로 아래 가상 예시를 사용할 수 있습니다.

조목이 아래의 여섯 표정 버튼을 누르면 인사·미소·활짝 웃음·생각·응원·다정함을 볼 수 있습니다. 직접 고르면 자동 전환이 멈추고 그 표정에 머뭅니다. **자동 전환 켜기**로 8초 간격 전환을 다시 시작할 수 있습니다. **움직임 멈추기**는 몸짓과 자동 전환을 함께 잠시 멈추며, **움직임 켜기**로 재개합니다. 기기에서 움직임 줄이기를 설정했다면 자동 움직임 없이 표정을 고를 수 있습니다.

홈의 표정은 미리보기입니다. 업무 화면에서는 작성 중·추가 확인·수정 반영·파일 준비 상태에 맞춰 등장하지만, 웃는 표정이 법적 검토나 결재 완료를 뜻하지는 않습니다. 공식 문서 파일에는 캐릭터가 들어가지 않습니다.

## 1. 필요한 일에 맞는 시작 위치

| 할 일 | 메뉴·화면 | 결과 |
|---|---|---|
| 입안 기준·부칙·절차를 묻기 | 입안 자료실 → AI 실무도움 → 기준 물어보기 | 원문을 인용한 설명과 확인할 사항 |
| 내가 쓴 조문 검토 | AI 실무도움 → 초안 검토 | 쟁점, 본문 정비 제안, 필요한 후속 확인 |
| 문장을 쉽게 바꾸기 | AI 실무도움 → 알기 쉬운 문장 | 표현 정비와 의미 변경 검토의 구분 |
| 의견제시 질의 준비 | AI 실무도움 → 의견제시 요청 준비 | 요청 요건 점검과 질의 작성 초안 |
| 기준서의 정확한 문장 찾기 | 입안 자료실 → 자료 검색 | 실제 발췌문과 원본 쪽수 |
| 참고자료 파일 내려받기 | 입안 자료실 → 원본 자료 5종 | PDF 4권, HWPX 서식, 출처 안내 |
| 다른 기관 규정 참고 | 새 작업의 유사 규정 또는 입안 자료실 | 실제 원문 최대 4개 비교 |
| 최근 5개년 제·개정 조사 | 조례 조사·5개년 비교 | 연도별 공포 기록, 과거 두 버전 조문 비교 |
| 기존 규정 일부개정 | 홈 → 기존 규정 고치기 | 개정안과 신·구조문대비표 등 문서 세트 |
| 새로운 규정 제정 | 홈 → 새 규정 만들기 | 조문 체계·초안·제정 문서 세트 |
| 상위법 개정 영향 확인 | 홈 → 상위법 영향 검토 | 기관 규정의 검토 후보와 전·후 원문 |
| 연결 시험·기관 서식 설정 | 설정·진단 | 실제 모델 응답, 법령 연결, 기관 프로필 |

자료 검색과 원본 내려받기는 AI 키 없이 사용할 수 있습니다. 실제 AI 설명·초안 생성에는 AI 연결이, 최신 법령과 다른 기관 규정을 가져오려면 공식 법령 API 연결이 필요합니다. 두 연결은 서로 별개입니다.

## 2. 입안 자료를 찾아 원문 확인하기

**자료 검색**에서 찾을 쟁점을 적습니다. “조례를 검토해 줘”보다 “기존 위원에게 연임 제한을 적용할 때 경과조치”처럼 한 가지 쟁점을 적으면 결과를 확인하기 쉽습니다. 규정 종류와 검토 관점을 고른 뒤, 필요하면 자료를 지정합니다. 자료 체크박스를 선택하지 않으면 전체 자료를 검색합니다.

화면의 검색어는 최대 800자입니다. 검색 결과는 AI가 다시 요약한 문장이 아니라 수록 자료에서 추출한 실제 발췌문입니다. 자료명, 판본, 수록 기준, PDF 실제 쪽수, 확인된 책자 쪽수와 공식 게시 페이지를 함께 확인하세요. **이 쪽 원문 보기**는 해당 PDF의 물리 페이지를 엽니다. 브라우저가 페이지 지정 기능을 지원하지 않으면 표시된 PDF 쪽으로 직접 이동하세요.

예를 들어 파일의 PDF 373쪽과 책자 365쪽은 같은 페이지를 가리킬 수 있습니다. 표지·목차 때문에 차이가 생기며, 부록에서 책자 번호가 다시 시작하는 자료도 있습니다. `PDF 쪽`을 원본 파일의 이동 기준으로 사용하고, `책자 쪽`은 인쇄 번호로 읽으세요. 고정 페이지가 없는 HWPX·TXT에는 PDF 쪽수를 만들어 붙이지 않습니다. [페이지 표시 계약](../src/lib/knowledge.ts)

결과가 없으면 법적 근거도 없다는 뜻이 아닙니다. 전문용어를 바꾸거나 질문을 나누고, 예상되는 자료를 선택해 다시 검색하세요. 전체 검색에서 다른 자료가 먼저 나올 때도 해당 자료를 지정하면 필요한 쪽을 찾을 수 있습니다. 결과가 있더라도 앞뒤 문맥과 예외는 원문으로 확인해야 합니다.

원본 자료 탭의 **판본·출처·파일 정보**를 펼치면 파일명, 수집·제공 시점, 공식 게시 페이지, 원본 SHA-256을 볼 수 있습니다. SHA-256은 제공 파일이 바뀌었는지 대조하는 값이며 공식 인증이나 최신성 보증이 아닙니다. 자료마다 이용 조건이 다릅니다. 법령 입안·심사 기준의 [공식 페이지](https://www.moleg.go.kr/menu.es?mid=a10105030000)는 공공누리 제4유형을 표시하므로 원본과 AI 작성 결과를 구분해 이용하세요.

## 3. 자료 근거로 AI 실무도움 받기

규정 종류를 먼저 고릅니다. 조례, 규칙, 훈령, 예규, 고시, 내부지침, 공공기관 내규, 법률·법령 중 실제 작업에 맞는 항목을 선택하세요. 같은 문장이라도 정할 수 있는 권한과 필요한 절차가 다를 수 있기 때문입니다.

질문은 **2~2,000자**, 본문은 **최대 12,000자**입니다. 초안 검토와 알기 쉬운 문장 모드에는 본문이 필수입니다. 전체 문서가 길다면 검토할 조문, 정의·적용범위, 관련 부칙 등 해당 쟁점에 필요한 범위를 선택해 넣으세요. 원문을 잘라 넣었다면 질문에도 검토 범위를 밝혀 주세요.

| 방식 | 질문 예 | 준비할 내용 |
|---|---|---|
| 기준 물어보기 | “일부개정과 전부개정을 고를 때 기준과 예외는 무엇인가요?” | 바꾸려는 범위와 규정 종류 |
| 초안 검토 | “위원 연임 제한을 바꾸는 초안에서 기존 위원에 대한 경과조치를 검토해 주세요.” | 현행·개정 조문, 관련 부칙, 정책 의도 |
| 알기 쉬운 문장 | “뜻은 유지하면서 다듬고, 권리·의무가 바뀔 수 있는 부분은 따로 표시해 주세요.” | 정확한 원문과 유지할 요건 |
| 의견제시 요청 준비 | “요청 자격과 질의 요건을 확인하고, 미확인 사실은 빈칸으로 남겨 주세요.” | 요청 기관, 입법 단계, 구체적인 해석 쟁점 |

예시 버튼은 질문을 채워 줄 뿐 자동으로 AI를 호출하지 않습니다. 문장 정비 예시에 들어가는 조문은 **가상 조문**입니다. 실제 작업에서는 자신의 원문으로 바꾸고 **자료 근거로 검토 요청**을 누르세요.

요청 중에는 실제 처리 상태를 표시합니다. 입력, 규정 종류, 검토 방식 또는 탭을 바꾸면 기존 요청을 중단하고 이전 결과를 지웁니다. 늦게 도착한 과거 응답이 새 질문의 답처럼 붙지 않도록 처리합니다. 중단 버튼은 입력 내용을 유지합니다. [자료실 구현](../src/components/KnowledgeWorkbench.tsx)

### 답변은 이 순서로 읽으세요

1. **실제 응답 모델**과 검색 시각·자료 버전을 확인합니다. 표시된 모델은 응답 기록이며 키가 존재한다는 표시와 다릅니다.
2. **검토 요약과 쟁점별 설명**에서 검토 범위와 전제를 읽습니다.
3. **원문 인용 대조** 아래 인용문을 읽고 링크로 해당 쪽을 엽니다. 예외·유의사항·적용대상을 앞뒤에서 확인합니다.
4. **본문 정비 제안**의 기존 문장·정비 문장·이유를 비교합니다. `표현 정비`, `내용 변경 검토`, `의미 확인 필요` 표시를 확인합니다.
5. **별도 확인할 사항**에서 현행 법령, 위임 근거, 기관의 사실관계와 정책판단을 확인합니다.
6. 필요한 경우 **검토문 복사** 또는 **출처 포함 검토문 내려받기**로 TXT를 저장합니다.

서버는 인용 ID가 실제 검색된 자료인지, 인용문이 그 발췌문 안에 있는지 대조합니다. 원문에 없는 인용과 본문에 없는 변경 전 문장은 제외합니다. 전부 제외되어 설명을 뒷받침할 인용이 없으면 답변을 보류합니다. 이 기계적 대조가 **인용문과 결론 사이의 법리적 관계까지 검증하는 것은 아닙니다**. 담당자는 실제 법령과 기관 사정에 적용할 수 있는지 따로 판단해야 합니다. [검증 코드](../src/server/knowledge-answer.ts)

문장 정비에서는 `및/또는`, 의무·재량, 금액·기간·숫자 순서, 적용 대상, 법인 포함 여부를 특히 확인하세요. 앱은 일부 조건 변화를 표시하지만 모든 의미 변화를 자동 판정하지 못합니다. 매뉴얼의 정비 전·후 사례에는 법적 내용까지 바뀐 사례도 있으므로 모든 사례를 무조건 치환하는 사전으로 사용하지 않습니다.

### 의견제시 요청 준비의 범위

이 기능은 법제처의 공식 답변이나 접수 완료가 아니라 **요청서 작성 준비**입니다. 요청 권한, 대상 규정, 업무 관련성, 입법 단계, 구체적 질의와 일반적 해석인지 등을 확인하고 필요한 사실을 준비합니다. 미확인 기관명·실무 사실·공포번호를 만들거나, 존재하지 않는 갑설·을설을 의무적으로 생성하도록 하지 않습니다. 실제 대립 의견이 없다면 그 사실을 유지하세요.

원본 HWPX 서식의 기입 예·체크 표시는 사용자의 실제 기관 사실을 뜻하지 않습니다. 자료실에서 서식을 내려받아 기관이 확인한 사실을 채우고 공식 절차에 따라 제출해야 합니다. 앱이 대신 제출하지 않습니다. 요청 범위와 절차는 [법제처 자치법규 의견제시 안내](https://www.moleg.go.kr/menu.es?mid=a10107010000)도 확인하세요.

### AI가 실패하거나 근거가 부족할 때

검색은 됐지만 AI 연결에 실패하면 가능한 원문 발췌와 출처는 남습니다. 자료 검색 탭에서 질문을 나누어 찾고, 설정·진단에서 실제 연결을 시험할 수 있습니다. 근거가 없으면 매뉴얼을 읽은 것처럼 답변을 꾸미지 않습니다. 연결 오류, 자료 부족, 확인되지 않은 인용은 서로 다른 상태로 읽어야 합니다.

자료실의 독립 검토 결과는 특정 작업에 자동 반영되지 않습니다. 현재 초안에 수정사항을 반영하려면 작업 화면의 조목이 검토를 사용해 필요한 문장을 선택하세요. 질문·본문·검색 발췌문은 설정한 AI 연결로 전달됩니다. 실제 전송 경로는 [연결 안내](API-SETUP.md)를 확인하세요.

## 4. 유사 규정 검색과 최대 4개 원문 비교

입안 자료실의 **유사 규정**을 엽니다. 법령·행정규칙·자치법규 중 검색 대상을 선택하고 실제 규정명이나 주제어를 넣으세요. 해당 화면에서 제공하는 기관 조건은 공식 조회 조건으로 사용하며, 모든 지자체의 규정을 미리 수집해 순위를 매기는 기능은 아닙니다.

결과의 제목·기관·시행일을 확인한 뒤 최대 4개 규정의 원문을 선택합니다. 비교는 실제 조회된 조 제목과 본문을 사용합니다. 서로 다른 기관의 제5조라는 이유만으로 같은 기능의 조문이라고 대응시키지 않습니다. 조 제목이 유일하게 대응되지 않으면 그대로 구분해 검토해야 합니다.

새 작업의 **위임 조항 원문 직접 넣기 · 유사 규정 참고**는 처음부터 펼쳐져 있습니다. 먼저 3개를 비교하고 필요한 사례가 있으면 4개까지 추가하는 방법을 권합니다. 검색어를 바꾸어도 선택은 유지되며, 넓은 비교표는 가로로 넘겨 볼 수 있습니다. **선택한 규정 모두 참고**로 여러 자료를 한 번에 작업에 넣습니다.

공식 원문 출처, 조회일, 시행일과 **부분 조회** 안내를 읽으세요. 본문만 확인된 경우 별표·별지·부칙까지 전부 비교했다는 뜻이 아닙니다. 공식 API 연결 실패로 저장본만 제공된 경우 이를 현재 유사 원문으로 선택해 성공한 것처럼 처리하지 않습니다. 이 검색은 AI 키 없이 가능하지만 운영자의 `LAW_OC` 연결이 필요합니다. [유사 규정 구현](../src/components/SimilarRules.tsx)

다른 기관의 좋은 문구라도 우리 기관의 사무, 위임 범위, 예산, 의회·집행기관 권한과 맞는지 확인하세요. 유사 규정의 존재는 우리 기관의 법적 근거를 대신하지 않습니다.

### 조례 조사·5개년 비교에서 이어가기

1. 상단 **조례 조사·5개년 비교**에서 주제어와 지역, 마지막 공포연도를 정합니다. 선택한 연도와 그 이전 4개 연도를 조사합니다.
2. 연도마다 현행·연혁 목록을 함께 읽습니다. 같은 공포 기록은 한 건으로 합치며, 통계는 검색 조건에 해당하는 **공포 기록** 기준입니다. 전국 조례 전체 수나 실제 정책 성과를 뜻하지 않습니다.
3. 남은 페이지가 있으면 이어서 조회하고, 오류가 있는 구간은 다시 조회합니다. 미조회 구간이 있는 결과를 전체 조사 완료로 보지 마세요.
4. 같은 조례의 서로 다른 공포 버전 2개를 담으면 실제 조문 차이를 봅니다. 조 제목이 중복되거나 대응이 불명확한 조는 별도 행으로 남습니다. 별표·서식은 원문에서 따로 확인합니다.
5. **현행판 참고에 담기**로 최대 4개를 모은 뒤 새 규정 참고자료로 가져옵니다. 개정할 때도 현행판을 다시 확인한 후 작업으로 넘깁니다. 과거 공포 버전을 현행 원문으로 가져오지 않습니다.

같은 탭에서 조사 결과를 전달하며 임시 전달값은 15분 동안 유효합니다. 작성 도중 조사를 열었다면 목적·개정 의도 등 입력값을 함께 복구합니다. 출처·조회 시각과 조사 메모도 작업 근거에 남깁니다. [조례 조사 열기](https://jomokjomok.vercel.app/law)

## 5. 기존 규정 일부개정

### 1단계 — 기관·규정 종류와 원문 선택

홈의 **기존 규정 고치기**에서 실제 기관 프로필과 규정 종류를 고릅니다. 원문은 직접 붙여넣기, 지원 파일 가져오기, 법령 API 검색으로 준비할 수 있습니다. 가상 기관 예시는 연습용입니다. 실제 기관으로 사용할 때에는 설정·진단에서 기관명·공고번호·담당 부서·절차를 먼저 확인하세요.

TXT와 HWPX의 텍스트를 읽습니다. HWP 바이너리, 스캔 PDF, 이미지 속 글자를 동일하게 읽을 수 있다고 기대하지 마세요. HWP 파일은 한글에서 HWPX 또는 텍스트로 저장하거나 본문을 복사할 수 있습니다. 복잡한 표·별표·서식이 있으면 가져온 결과를 원본과 대조해야 합니다.

### 2단계 — 원문 구조 확인

조·항·호, 조 제목, 별표와 인용이 제대로 나뉘었는지 확인합니다. 공식 API를 사용했더라도 본문만 읽었거나 일부를 조회한 상태일 수 있습니다. 원문 검토 경고가 있으면 원문을 보완하거나 해당 위험을 확인하고 진행하세요. 저장본은 표시된 날짜의 일부 자료이며 최신 원문으로 자동 승격하지 않습니다.

### 3단계 — 개정 의도와 실제 근거 입력

“무엇을 어떻게 바꾸며 누구에게 적용할지”를 적습니다. `위임 조항 원문을 알고 있어요` 입력을 사용하는 경우 실제 위임 조문을 최대 6,000자 안에서 넣고 출처·확인일을 정확하게 적으세요. 이는 사용자 제공 원문으로 남으며 입력한 사실만으로 공식 조회가 검증된 것은 아닙니다.

`유사한 다른 기관 규정을 먼저 찾아보고 싶어요` 흐름에서는 실제 조회한 규정을 참고자료로 선택합니다. 위임 조문과 유사 사례는 서로 다른 역할입니다. 알 수 없는 공포번호나 상위법 근거를 그럴듯하게 작성하지 말고 미확인 상태로 남기세요.

### 4단계 — AI 변경 제안 확인

개정 계획은 변경 명세로 제안됩니다. 삭제·신설·문구 교체·조 번호 이동의 범위가 의도와 맞는지 하나씩 확인하고 채택하거나 수정합니다. 입안 참고자료가 검색되면 작업의 **입안 참고자료** 패널에서 전달된 원문을 볼 수 있습니다.

### 5단계 — 인용 정합성과 점검 결과 검토

번호 이동으로 영향을 받는 조문·별표·서식 인용을 확인합니다. 자동 계산 가능한 연결과 법적 타당성 판단은 구분해야 합니다. 엔진이 찾은 연결을 담당자가 제외할 수 있지만, 제외 이유와 제출 문서의 최종 인용 관계는 다시 확인하세요.

### 6단계 — 이유·주요내용과 부칙 확정

확정한 변경에 맞춰 이유·주요내용을 작성하고 검토 확인을 합니다. 시행일·적용례·경과조치는 서로 다른 문제입니다. 어떤 사람·신청·처분·기간에 종전 규정을 유지할지 구체적으로 정하세요. 앱의 기본 문구만으로 기관의 모든 전환 상황이 처리되지는 않습니다.

### 7단계 — 문서 세트 확인·저장

문서 미리보기에서 개정안, 신·구조문대비표, 이유·주요내용, 예고·의견조회 문서, 입안 점검표, 개정 후 전문 참고본을 함께 봅니다. 명세를 고친 뒤에는 관련 검토 상태를 다시 확인하고 새로운 파일을 받으세요. 개정 후 전문은 검토 참고본이며 별도 공포 형식을 대신하지 않습니다.

## 6. 새 규정 제정

목적·적용 대상·규정 종류·실제 근거와 기관 정보를 준비합니다. AI는 먼저 조문 체계를 제안하고, 담당자가 이를 확인한 뒤 조문 초안을 작성합니다. 목적·정의·적용범위·실체 규정·절차·보칙·부칙의 구성이 실제 정책과 맞는지 살펴보세요. 모든 규정에 같은 장과 조를 기계적으로 넣는 방식은 적절하지 않을 수 있습니다.

조문 체계 확인, 각 조문 초안 검토, 이유·주요내용 확인을 거쳐 문서 세트를 만듭니다. 법률상 위임이 필요한 의무·제재·재정 지출을 매뉴얼이나 타 기관 사례만으로 허용된 것으로 보지 마세요. 확인되지 않은 근거나 기관의 사실은 작성 필요 항목으로 남겨 두고 실제 자료로 보완합니다.

초안은 전체 체계를 참고하면서 **최대 3개 조씩** 작성합니다. 진행 화면에는 경과 시간과 실제 완료한 조문 수를 표시합니다. 완료 묶음을 저장한 뒤 다음 묶음을 요청하며, 중단하거나 오류가 나면 **남은 조문 이어 쓰기**로 재개합니다. 이미 작성하거나 직접 수정한 조문은 보존합니다. 저장 오류가 표시되면 페이지를 닫기 전에 보관파일을 받아 내용을 지키세요.

전체 작업을 54초에 끝내던 제한은 제거했지만 한 번의 서버 요청에는 최대 300초의 호스팅 한도가 있습니다. 브라우저를 닫은 동안 새 조문을 계속 생성하는 백그라운드 작업은 아니며, 다시 열어 저장된 내용부터 이어 씁니다. 작성 중이거나 빈 조문이 남아 있으면 이유서·점검을 완료로 표시하지 않습니다.

제정 문서의 기본 구성은 제정안, 제정이유·주요내용, 조문 체계표, 규정 종류별 예고·의견조회 문서, 입안 점검표입니다. 기존 규정의 일부를 고치는 작업인지, 전부개정인지, 폐지 후 제정인지 애매하면 먼저 기준 물어보기에서 형식의 쟁점을 확인한 뒤 작업 종류를 선택하세요.

## 7. 조목이와 작업 안에서 검토하고 반영하기

화면 위 **다음 할 일**은 현재 조문·점검·문서 단계에서 무엇을 할지 안내합니다. 실제 행정 절차는 **이후 행정 절차 한눈에 보기**를 펼쳐 확인합니다. 앱 문서 작성과 관계부서 협의·의결·공포 완료는 구분합니다.

**조목이와 이 단계 검토** 또는 옆의 **이 작업 이어서 검토**를 누르면 같은 작업 화면에 검토 도구가 열립니다. 제정은 작성 중인 초안, 개정은 현재 수락한 변경을 반영한 본문을 사용합니다. 범위가 길면 조문과 부칙을 선택해 12,000자 이내로 나누어 검토합니다. 본문을 임의로 잘라 보내지 않습니다.

1. 검토 범위와 질문을 확인하고 **AI 검토 요청**을 누릅니다. 질문·선택 본문·검색 발췌문은 설정한 AI 연결에 전달됩니다.
2. 큰 글씨의 검토 의견과 수정 전·후 문장을 먼저 읽습니다. **근거 인용 펼쳐 보기**에서 실제 출처와 인용문을 대조합니다.
3. 반영할 수정안의 체크박스를 선택하고 **선택한 수정 반영**을 누릅니다. 선택한 문장만 현재 초안에 반영하며 조문·점검·문서가 함께 갱신됩니다.
4. **이번 반영 되돌리기**로 이번 수정만 되돌릴 수 있습니다. 반영 뒤 조문을 직접 고쳤다면 후속 수정을 덮어쓰지 않도록 자동 되돌리기를 멈춥니다.

동일한 문장이 여러 곳에 있거나 검토 후 본문이 바뀐 경우, 수정 범위가 겹치는 경우에는 자동 반영하지 않습니다. 제목·부칙·조 구조 변경처럼 정확한 문장 교체로 처리하기 어려운 제안도 직접 검토하도록 안내합니다. 일반적인 검토 의견만 있고 정확한 수정 문장이 없으면 자동 적용 항목은 생기지 않습니다.

최신 검토와 선택·반영 기록은 브라우저 작업에 저장되고 작업 보관파일에 포함됩니다. 기관의 법적 결재 기록을 대신하지 않습니다. 초안을 고친 뒤에는 **현재 초안 새로 불러오기**로 새 내용으로 검토하세요.

입안 참고자료는 최근 AI 요청에 실제 전달한 제목·쪽수·판본·검색 상태를 보여 줍니다. **전체 검색 기록**은 같은 역할의 최신 기록 최대 12개를 보관합니다. 독립 **입안 자료실**에서 한 검토는 특정 작업에 자동 연결되지 않으므로, 수정까지 이어가려면 작업 안의 조목이 검토를 사용하세요.

## 8. 상위법 개정 영향 검토

상위법 개정 전 원문, 개정 후 원문, 기관 규정의 세 입력을 준비합니다. 현재 입력 한도는 상위법 전·후 각각 12,000자, 기관 규정 24,000자입니다. 같은 시행시점·같은 법령의 전후본인지 직접 확인하고 검토 범위를 밝혀 주세요. [영향 검토 입력](../src/app/impact/page.tsx)

결과에서는 상위법 전·후 인용과 기관 조문 인용이 실제 입력에 존재하는지 확인합니다. 자동 후보 연결은 전후 같은 조 번호로 대응되는 본문을 중심으로 하므로 신설·삭제·가지번호 변경·조 이동·별표의 영향까지 포괄한다고 해석하면 안 됩니다. 선택하지 않은 후보는 개정 작업에 자동 반영되지 않습니다.

AI 연결이 실패했을 때 직접 인용 문자열로 찾은 후보는 그 방식으로 표시합니다. 문자열 연결만으로 반드시 개정해야 한다고 판단하지 않습니다. 인용문 세 개가 존재하더라도 법적 영향의 결론은 담당자가 검토합니다. 개정 필요성이 확인된 후보만 새 작업으로 이어가세요.

## 9. 근거 표시 읽기

| 표시·유형 | 의미 | 확인할 사항 |
|---|---|---|
| 실시간 공식 조회 | 해당 요청에서 공식 API로 받은 내용 | 실제 제목·시행일·조회일·조회 범위 |
| 승인된 중계 조회 | 등록된 중계를 통해 공식 데이터 조회 | 원 출처·조회일·운영자의 승인 설정 |
| 저장본 | 표시된 시점에 보관한 일부 원문 | 이후 개정, 빠진 조문·별표, 현행성 |
| 사용자 제공 | 사용자가 붙여넣거나 파일로 넣은 내용 | 원본 일치, 출처, 버전과 적용 시점 |
| `KB-…` | 수록 매뉴얼·서식의 참고 발췌 | 기관·규정 종류별 적용 범위와 예외 |
| `EV-…` | 실제 규정·위임 근거 등 작업 원문 | 조회 방식과 정확한 조문·시행일 |
| 예시 응답 | 미리 작성한 시연용 응답 | 실제 모델 실행이나 기관 사례가 아님 |

문서 해시가 일치하는지 확인하는 기능과 원문의 최신성을 확인하는 기능은 다릅니다. 조회 당시 원문을 보관해도 시간이 지나면 새 개정이 있을 수 있습니다. 최종 제출 전 필요한 현행 원문을 다시 확인하세요.

## 10. 문서 다운로드와 작업 보관파일

화면에 문서가 만들어졌다면 DOCX, HWPX 또는 두 형식을 선택해 받을 수 있습니다. 검토가 남았거나 일부 조문이 미작성인 경우 파일명과 본문에 **검토용 초안** 및 남은 확인사항을 표시합니다. 다운로드해도 조문·이유서 확인 상태가 자동으로 바뀌지 않습니다. 한글에 붙여넣기용 복사도 사용할 수 있습니다. 한글 프로그램에서 표·밑줄·줄바꿈·글꼴·쪽 나눔을 확인하고, 기관 서식과 맞추세요.

각 문서 아래 **이 문서 HWPX 받기 / 이 문서 DOCX 받기**로 예고문이나 점검표만 따로 받을 수 있습니다. **예고문에 들어갈 정보**에서 공고번호·공고일·의견 제출기한·공고 주체·부서·주소·전화·이메일·제출방법을 입력하면 미리보기와 두 파일 형식에 함께 반영됩니다. 입안 점검표는 항목마다 미확인·확인·보완 필요·해당 없음을 선택하고 검토 메모를 적습니다. 작업 본문이 바뀌면 이전 점검의 유효성을 다시 확인합니다.

자치법규 입안 길라잡이의 편집 기준과 예고 필수 항목, 입안 단계별 점검 내용을 반영했습니다. 제공 자료에 독립된 완성 예고문 서식이 없는 부분은 **매뉴얼 기준 재구성**으로 표시하며, 공식 원본 서식과 동일한 파일이라고 주장하지 않습니다. [서식별 원문 근거와 검증 범위](research/v05-form-mapping.md)

HWPX는 실험적 출력입니다. XML과 ZIP 구조가 정상이라는 검사만으로 모든 한컴 한글 버전에서 열기·편집·저장까지 검증된 것으로 보지 않습니다. 파일이 열리지 않으면 같은 DOCX 또는 붙여넣기용 복사를 사용해 마무리할 수 있습니다. 외부에서 수정한 문서는 원래 작업으로 자동 역동기화되지 않습니다.

| ZIP의 추가 파일 | 용도 |
|---|---|
| `작업백업.jomok.json` | 원문·변경·조목이 검토·반영 기록·기관 스냅샷을 다른 브라우저에서 복원 |
| `문서검토상태.txt` | 문서별 미확인·미작성 항목과 검토용 여부 |
| `근거원문.txt` | 조회·입력 당시 실제 작업 근거 원문 보존 |
| `입안참고자료_검색기록.txt` | AI에 전달한 참고자료의 버전·쪽수·발췌문 보존 |
| `사용기록.csv` | 사용자가 기록·선택한 작업시간·수정·평가값 |
| `읽어보세요.txt` | 초안·파일 이용과 복원 안내 |

파일 생성 뒤 자동 다운로드가 시작되지 않으면 **준비된 파일 다시 저장**을 누르세요. 내용을 수정했으면 새로 파일을 만들어 받아야 합니다.

파일명·포함 조건은 [문서 작업 화면](../src/components/work/DocsTab.tsx)과 [출력 코드](../src/lib/export.ts)를 기준으로 합니다. 참고자료 검색이 없으면 해당 기록 파일도 그 상태를 나타냅니다.

홈의 **보관한 작업 불러오기**에서 10MB 이하 작업 JSON을 선택할 수 있습니다. 형식과 무결성을 확인한 뒤 새 작업으로 복원하며 현재 작업을 덮어쓰지 않습니다. 참고자료 인용은 백업에 적힌 자체 해시뿐 아니라 앱에 등록된 정본 지문과도 대조합니다. 문자와 해시를 같이 바꾼 파일을 공식 참고 인용으로 받아들이지 않기 위한 검사입니다. 이 검사가 공인 전자서명이나 법적 효력을 부여하지는 않습니다.

보관파일에는 API 키·AI 연결 주소와 비밀키를 넣지 않습니다. 다만 작업 원문과 사용자가 적은 실제 근거·기관 설정은 들어가므로 해당 업무 문서로 관리하세요. 브라우저 데이터를 지우거나 기기를 바꾸기 전에는 파일로 보관하는 것이 좋습니다.

## 11. 우리 기관 설정 만들고 옮기기

**설정·진단 → 우리 기관**에서 **새 기관 만들기**를 누릅니다. 기본 3개 예시 기관은 원본을 직접 고치는 대신 복제해 새 기관을 만듭니다. 브라우저에 사용자 기관을 최대 20개 보관할 수 있습니다.

설정 가능한 값은 기관명·기관 유형·기관장 명칭·법제 부서·의회 명칭·공고번호·의견 제출 연락처·계산용 예고일수·대비표의 6가지 표기·규정 종류별 절차·확인 메모입니다. 절차는 종류마다 최대 25단계이며 필요한 문서, 계산용 일수, 근거와 주의사항을 적을 수 있습니다. [기관 설정 계약](../src/config/profiles.ts)

기간 값은 일정 계산과 안내를 위한 사용자 설정입니다. 국가 법령의 예고기간을 지자체·공공기관의 모든 규정에 자동 강제하거나, 입력한 기간이 법적으로 확정됐다고 판정하지 않습니다. 기관의 실제 근거와 예외를 확인하고 확인 표시를 저장하세요. 설정을 바꾸거나 외부 기관 파일을 가져오면 확인 상태를 다시 점검해야 합니다.

**기관 설정 내보내기**로 받은 JSON은 **다른 기관 설정 불러오기(JSON · 256KB 이하)**로 이동할 수 있습니다. 불러온 기관에는 새 ID를 부여하고 확인 상태를 해제합니다. 기관 이름·담당 부서·연락처·절차가 현재 기관에 맞는지 확인한 뒤 **기관 설정 저장**을 누르세요. 이 파일에는 AI 키와 연결 주소를 포함하지 않습니다.

새 제·개정 작업은 시작 당시 기관 설정을 `profileSnapshot`으로 보관합니다. 이후 설정 수정·삭제가 기존 작업의 문서 서식과 절차를 함께 바꾸지 않습니다. 작업 보관파일로 복원한 기관 설정은 해당 작업에서 계속 사용되며, 미리보기에 `(작업에 보관됨)`이 표시될 수 있습니다. 기관 선택 목록에 자동 등록되는 것은 아니므로 새 작업에도 쓰려면 기관 JSON을 별도로 가져오세요.

이전 v0.3 작업처럼 기관 스냅샷이 없으면 기존 기본 기관 ID로 호환하며, 알 수 없는 기관은 복원 과정에서 선택이 필요할 수 있습니다. 작업 화면의 **다음 할 일**에서 기관 설정의 확인 상태, 기한, 필요 문서와 메모를 다시 확인하세요.

## 12. 작업시간과 실무 효과 기록

사용기록은 사용자가 시작·일시정지·재개·종료를 선택하고 수정·평가값을 기록하는 기능입니다. 브라우저를 닫는 것만으로 기록 시간이 자동 일시정지되지는 않을 수 있으므로 쉬는 시간은 일시정지를 사용하세요. 작업 복원은 진행 중 타이머를 그대로 재개하지 않습니다.

업무효과를 비교할 때에는 앱 안에서 문서를 만드는 시간뿐 아니라 내려받은 뒤 한글에서 다듬고 검토하는 시간까지 같은 기준으로 재세요. 동일하거나 난이도가 비슷한 업무를 실제 직원이 수행한 결과와 비교해야 합니다. CSV는 사용자 기록이며 자동 검증된 시간 절감률 또는 법률 품질 점수가 아닙니다. [사용기록 기능](../src/lib/evaluation.ts)

## 13. API 연결과 실패 해결

운영자 기본 연결은 서버의 `GOOGLE_API_KEY` 등 키를 사용합니다. 기본 Gemma 모델은 `GEMMA_MODEL=gemma-4-31b-it`, 기본 우선 연결은 `DEFAULT_MODEL_ID=gemma4-31b@google`입니다. `GOOGLE_MODEL`은 기존 설정 호환 변수로 남습니다. Groq 선택 연결은 `GROQ_API_KEY`와 `GROQ_GPTOSS_MODEL`, OpenAI 선택 연결은 `OPENAI_API_KEY`와 `OPENAI_MODEL=gpt-5.4-mini`를 사용합니다. 모델 이름을 바꿨으면 실제 요청을 다시 시험하세요.

**설정·진단**의 모델별 실제 응답 시험을 실행하세요. `키 설정됨`은 인증·모델 접근·할당량·응답 구조가 모두 정상이라는 뜻이 아닙니다. 실제 응답 모델과 오류 메시지를 확인한 다음 짧은 자료 근거 검토, 실제 초안과 문서 다운로드까지 시험해야 합니다. 기본 연결의 자동 모델 선택과 사용자가 지정한 모델의 엄격한 시험은 구분됩니다.

개인 키 연결은 선택한 제공자의 키를 브라우저 세션에 보관합니다. 기관 AI 연결은 운영자가 허용한 OpenAI 호환 주소만 사용할 수 있습니다. 사용자 입력 칸에 기관 서버 주소를 적었다고 공개 앱 서버의 데이터 전송이 자동으로 내부망에만 머무는 것은 아닙니다. 필요한 경우 앱도 기관 환경에 배치해야 합니다.

최신 법령·유사 규정은 법제처에서 신청·승인받은 `LAW_OC`가 별도로 필요합니다. 이 값을 이메일 앞부분 등으로 추측하지 마세요. 현재 운영 도메인의 Vercel 프로젝트는 `kevin-jeong/jomokjomok-law`이며, 운영자는 **Production 환경에 저장한 뒤 재배포**해야 합니다. 상세 발급·설정·오류별 조치는 [API 연결 안내](API-SETUP.md)를 따릅니다.

비밀키는 채팅, Git 저장소, 공개 `NEXT_PUBLIC_*` 변수에 넣지 마세요. 문제를 공유할 때에는 오류 코드·실제 모델명·배포 식별자·시각을 보내면 되고 키 원문은 필요하지 않습니다.

## 14. 제출 전에 확인할 것

- 실제 규정 종류와 기관의 사무·권한·위임 범위를 확인했는가?
- 현행 법령의 제목·조문·시행일·부칙과 별표까지 필요한 범위를 확인했는가?
- AI 제안의 적용 대상·금액·기간·의무·재량·예외가 정책 의도와 맞는가?
- 시행일·적용례·경과조치가 기존 신청·처분·위원·계약 등에 미치는 영향을 확인했는가?
- 변경 명세, 이유·주요내용, 개정문, 신·구조문대비표가 같은 최종안을 가리키는가?
- 기관 프로필의 공고번호·연락처·절차·기간을 실제 근거에 맞게 확인했는가?
- 내려받은 파일을 실제 제출 환경에서 열고 편집·저장까지 확인했는가?
- 원문과 참고자료, 필요한 작업 보관파일을 함께 보관했는가?

이 목록은 담당자의 검토를 돕기 위한 것이며 모든 규정의 쟁점을 빠짐없이 포함하지는 않습니다. 앱의 개발용 검색 적중률을 제출 문서의 법적 정확도로 읽지 마세요. 실제 확인한 기능·오류·제한은 [v0.5 검증 기록](VALIDATION-v0.5.md)에서 확인하며, 이전 [v0.4 검증 기록](VALIDATION-v0.4.md)과 [v0.3 검증 보고서](VALIDATION-v0.3.md)는 그 버전에 한정됩니다.
