## 검증한 실패 처리

인용·AI 도움·자료 백업 통합 55개 테스트에서 다음을 확인했다.

- 근거 없는 생활 질문에 AI를 호출하지 않는다.
- 클라이언트가 주입한 참고자료 대신 서버 검색 결과를 사용한다.
- 존재하지 않는 ID, 원문 밖 인용, 사용자 문서에 없는 변경 전 문장을 제외한다.
- 일부 인용을 제외하면 그에 의존할 수 있는 요약·초안을 그대로 재사용하지 않는다.
- 숫자 순서, 의무·허용, 범위, `하지 않는다`·`하지 못한다` 등 조건 변화는 내용 변경 검토 대상으로 표시한다. 이 탐지가 모든 의미 변화를 포괄하는 것은 아니다.
- 네 가지 도움 모드, 질문 2,000자·본문 12,000자 경계, 빈 검토문과 잘못된 요청을 검증했다.
- AI가 실패하면 실제 검색 원문을 남기고 실패 상태를 구분한다.
- 보관파일의 외부 해시를 다시 계산해도 원문·페이지·메타데이터 변조는 정본 대조에서 거부한다.
- 공식 EV 근거와 KB 입안 참고자료는 별도로 보존한다.

## 운영 배포와 직접 사용

### 실제 AI와 문서 작성

`b40bc90`에서 기존 서버의 Google 연결을 실제 사용했다. 예시 응답과 강제 법령 오프라인 설정은 사용하지 않았다. 가상 한빛시의 작은 내부 지침을 시험 입력으로 사용했다. [브라우저 실행 기록](validation/v04-browser-live.json)

| 개정 | 제2조 제출기한 3일→5일 제안 1건을 수락하고 개정문·대비표·전문 일치 확인 | 계획 작성 6.7초 |

자료 근거 검토에서는 **인용·변경 제안 1개가 원문 대조를 통과하지 못해 제외**됐고, 검토 사항 2개를 남겼다. 요약도 중립 문구로 바뀌었다. 이 결과를 인용 정확도 100%나 질문의 모든 기준을 완전히 설명한 결과로 집계하지 않는다. [실제 내려받은 검토문](validation/v04-rag-live.txt) · [화면](screenshots/v04-rag-live.jpg)

개정 이유서에는 AI가 추론한 추가 목적을 그대로 두지 않고 담당자 검토 역할에서 제출기한 변경 사실만 남기도록 직접 수정한 뒤 확인했다. 제정 이유서는 입력 목적과 일치하여 수정 없이 확인했다. 두 가상 작업은 상위법을 명시하지 않아 공식 위임 근거 조회가 건너뛰어졌으며, 이를 상위법 적합성 검증 성공으로 표시하지 않는다.

### 실제 문서 검사와 배치 수정

초기 다운로드의 DOCX 11종, 총 15쪽을 렌더링해 모두 육안 검수했다. 한글 글꼴이 없는 검증 환경에는 공식 Noto CJK 글꼴을 임시로 등록했고 원본 문서는 바꾸지 않았다. HWPX 11종은 패키지 CRC·XML·DOCX와의 본문 일치를 검사했다. 작업 백업의 지문, 공식 근거와 입안 참고자료 기록의 구분도 확인했다.

초기 예고문 두 건에서 마지막 일부 항목만 2쪽으로 넘어가는 문제를 발견했다. 공통 문서 모델의 빈 문단 3개를 제거하고 내용·글꼴·글자 크기·행간·문단간격·A4 여백을 유지한 채 두 예고문을 각각 1쪽으로 다시 렌더링해 확인했다. `0f7f54a` 배포 후 두 작업을 다시 내려받았고, 실제 예고문의 본문·서식 XML이 검수한 수정본과 정확히 일치했다. 최종 다운로드를 별도로 재렌더했다고 표현하지 않는다.

### 화면 연결과 배포 확인

작업 기록의 고정 위치 때문에 자료실 연결 버튼이 가려지는 현상을 직접 확인했다. 두 패널을 문서 흐름에 배치하도록 고친 뒤, `0f7f54a`에서 마우스로 연결하고 제정 질문 210자·3개 조문 본문 188자가 자료실에 전달되는 것을 확인했다. 질문과 본문은 URL에 포함되지 않았다.

기관 설정 생성·저장과 JSON 생성은 앞선 운영 화면에서 확인했다. **기관 설정 가져오기 UI는 미완료**로 남긴다. 이번에 완료한 작업 백업 복원과 혼동하지 않는다. 복원은 같은 브라우저에서 별도 작업으로 확인했으며 다른 기기 간 복원 시험은 아니다.

`0f7f54a`의 GitHub Actions는 테스트·빌드·타입 검사를 모두 통과했다. 운영 도메인에서 v0.4.0·`0f7f54a`·`icn1`, 자료 6종·1,997쪽·2,283개 색인과 실제 법령 진단을 확인했다. [CI 결과](https://github.com/kebong-3/jomokjomok/actions/runs/40178495574) · [Vercel 운영 배포](https://vercel.com/kevin-jeong/jomokjomok-law/J4uixzQ9mfQvsvWeJagufG85Yami)

### 이전 실패와 연결 상태

첫 배포 `01bbc07`에서는 Gemma 짧은 연결 시험이 성공해도 실제 자료실 설명이 시간 초과됐고, Groq는 HTTP 401을 반환했다. Gemma의 호출 시간·출력 예산과 검색 문맥을 조정한 뒤 위 실제 생성 결과를 확인했다. 10월 25일 수정 후 Google 생성 성공은 확인했지만 Groq 키를 교체하거나 다른 제공자를 실제로 생성 시험하지는 않았다. OpenAI 연결도 구현되어 있으나 운영 키가 설정되지 않은 상태다.

원본 6종은 10월 25일 재다운로드하여 크기와 SHA-256 일치를 확인했고, 색인 재생성도 같은 지문을 얻었다. [최초 운영 API와 원본 지문 기록](validation/v04-live-api.json)

## 남는 검증 범위

인용 문구의 존재와 법적 해석의 타당성은 다르다. 실제 기관 안건에 대한 법무 검토, 직원의 기존 방식 대비 시간·수정 건수 측정, 한컴 한글에서 HWPX 열기·편집·인쇄, 기관별 운영·권한·감사·백업 요구사항 확인은 별도다. 이를 수행하지 않은 상태에서 98점 달성이나 법률 정확도를 보증하지 않는다.
